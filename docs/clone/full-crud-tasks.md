# 전체 메뉴 풀스택 CRUD 실행 작업표

기준: 2026-10-24. 기존 `implementation-plan.md`의 S1~S9 완료는 수집 화면·메모리 도메인 엔진·결정적 외부 Provider 계약 검증 범위였다. **전체 메뉴의 영속 CRUD 화면 완료와는 다르다.** 이 문서가 후속 실행 상태의 기준이다.

## 완료 판정

각 메뉴는 모델·입력 검증·권한·API·화면·회귀 테스트가 연결되어야 완료다. 생성 → 목록/상세 조회 → 수정 → 새로고침 및 다른 세션에서 조회 → 삭제 → 관련 데이터 정리를 확인한다. 실패 시 성공 알림을 내지 않고 입력을 유지한다. 사용자는 자신이 속한 워크스페이스만 접근한다. 계정 소유 기능인 추천·피드백은 선택 워크스페이스와 독립적으로 본인 자료를 관리하며, 피드백은 별도 서비스 운영자에게도 열람을 허용한다. 작업 대상은 현재 선택한 워크스페이스 ID이며 기본 데모 UUID를 강제하지 않는다.

집계/분석 페이지는 원본 측정값을 직접 수정하는 대신 그 페이지의 설정·저장된 분석·메모를 CRUD하고 원본 데이터 변경을 집계에 반영한다. 결제/사용량 원장은 서버 작업으로만 생성하고 취소·환불·예약 해제도 별도 명령으로 처리한다.

## 0. 공통 기반 및 현재 증거

- [x] F01 영속 저장: 기존 REST/RPC/함수/로그인 모두 `PersistentHaloXStore` 사용. SQLite WAL 파일 기본 경로 `data/halox.sqlite`, 환경변수 `HALOX_DATABASE_PATH`로 지정. 변경은 트랜잭션 단위로 반영한다.
- [x] F02 재시작·동시성·원자성: 별도 Node 프로세스에서 읽기/삭제, 동시 비동기 작업의 갱신 유실 방지, 실패 시 롤백, 시드 삭제 유지, 손상 저장소의 자동 초기화 금지 테스트. SQLite 확장 잠금 오류(261 등)도 비동기 재시도하며 도메인 변경은 한 번만 실행한다.
- [x] F03 비공개 인증 자료: OTP·인증 토큰 해시·비밀번호 해시·로그인 세션·민감 인증 시도를 REST 테이블 목록 밖에 저장. 신규 가입자의 비밀번호는 scrypt. 시드 계정은 기존 환경변수 자격증명 사용.
- [x] F04 공개 REST의 인증/플랜 변경 제한, 멤버 자기 권한 상승 방지, 워크스페이스 소유자 보호, API 키 전체 비밀값 검증. 서버 도메인 작업과 공개 REST 권한을 분리한다.
- [x] F05 E2E는 실행마다 별도 SQLite 파일 사용. 개발 DB를 건드리지 않으며 테스트가 종료되면 파일을 정리한다.
- [x] F06 워크스페이스 목록/선택을 서버 ID 기준으로 전환. 임의 기본 항목 및 localStorage 레코드 병합 제거.
- [x] F07 매니페스트의 앱 메뉴·탭·상세 화면을 서버 라이브 화면으로 전환하고 CRUD 성공은 서버 응답 이후에만 표시. 캡처 폴백의 localStorage 동작은 공개/레거시 재현용이며 완료 대상 앱 메뉴의 저장소로 사용하지 않는다.
- [x] F08 공통 `WorkspaceProvider`의 선택 ID 재검증·탭 간 전환·오류 재시도를 모든 워크스페이스 CRUD에 적용. 레거시 동기화 경로의 `DEFAULT_WORKSPACE_UUID`도 제거하고 현재 선택 ID를 명시적으로 전달한다. 계정 소유 자료는 공통 인증 상태로 독립 조회한다.
- [x] F09 완료 대상 26개 도메인의 필수값·길이·참조·중복·버전 충돌·권한·삭제 정책을 적용하고 도메인 단위/통합/E2E로 검증. 모델/API/테스트 매핑은 [최종 인수 기록](final-acceptance.md)과 `crud-coverage.json`에 고정한다.
- [x] F10 실제 비동기·중복 위험 작업의 영속 요청 키, 점유·커서, 취소, 원자적 저장과 재시작 복구를 적용. 조회 RPC 읽기 전용 정책과 전체 저장 상태의 SHA-256 백업·원자적 복원 도구를 추가했다. 동기 CRUD와 외부 Provider 단일 요청은 저장 트랜잭션·불확실 상태 기록으로 처리한다.

현재 SQLite는 기존 도메인 엔진의 전체 상태를 버전 있는 JSON 스냅샷으로 트랜잭션 저장한다. 로컬/단일 서버에서 실제 영속성을 제공하지만 정규화된 Postgres 구현은 아니다. Supabase SQL 마이그레이션은 별도 검증 자산으로 남아 있으며 이 런타임과 연결하지 않았다. 여러 서버가 파일을 공유하는 배포나 대규모 데이터에는 DB 어댑터 교체가 필요하다. 런타임 저장 파일과 비밀키는 Git에 포함하지 않는다.

최종 검증(2026-10-24): **단위 349/349, 백엔드 22/22(RPC 36·테이블 59), 전체 E2E 112/112**, 타입 검사·프로덕션 빌드 통과. 경로 **363개**에서 누락·실패·중복·위험 URL·자산 누락 0개이며 원본 404 73개는 기능 완료 수에 포함하지 않는다. 완료 대상 278개를 26개 서버 도메인에 미매핑 0개로 연결했다. 공개 캡처 195개 카탈로그, 초안/게시 버전 분리, 운영자 권한, 문의 접수/상태/삭제, SQLite 읽기 경합 재시도, 전체 상태 백업·복원을 검증했다. 실제 SMTP/OpenAI/SOLAPI/Google/NicePay 요청은 수행하지 않았다. 상세는 [최종 인수 기록](final-acceptance.md)에 기록했다.
