# 계정 복구·프로필·세션 관리

2026-10-23. 전체 메뉴 작업표 A03/S01 범위. 회원가입 때 인증한 전화번호로 비밀번호를 재설정하고, 로그인 후 이름·전화번호·비밀번호·활성 세션을 관리한다. 설정의 다른 탭과 전체 메뉴 완료를 뜻하지 않는다.

## 화면과 API

| 화면 | 동작 | API |
|---|---|---|
| `/app/settings?tab=profile` | 프로필 조회, 이름 수정, 인증된 전화번호 변경, 비밀번호 변경, 현재/다른 세션 로그아웃 | `GET/POST /api/v1/account` |
| `/app/forgot-password` | 이메일/등록 전화번호 입력 → 문자 인증 → 새 비밀번호 저장 → 로그인 | `POST /api/v1/auth/recovery` |
| `/app/reset-password` | 같은 복구 절차의 진입 경로 | 같은 복구 API |
| `/app/login` | 비밀번호 검증 후 서버에 등록된 세션 발급 | `POST /api/v1/auth` |

계정 메뉴에 ‘내 프로필과 보안’을 추가했다. 프로필 화면은 계정 소유 데이터이며 워크스페이스를 전환해도 바뀌지 않는다. 일반/워크스페이스/멤버 설정으로 이동할 수 있다. 이메일 변경, 계정 삭제, 다중 인증 등록은 이번 S01 범위에 포함하지 않았다.

`/api/v1/account`의 명령은 `profile-update`, `phone-send`, `phone-verify`, `phone-update`, `password-update`, `session-revoke`, `sessions-revoke-others`다. 요청에서 user_id를 지정해도 인증된 계정의 자료만 변경한다. 세션 종료는 본인 세션만 가능하다. 성공 조회·변경 응답은 캐시하지 않는다.

이름은 1~100자이며 `expected_revision`으로 다른 화면과의 수정 충돌을 감지한다. 기존 REST 이름 수정도 버전을 올리므로 전용 화면의 오래된 수정은 409다. 전화번호·인증 시각·비밀번호·세션을 공개 REST로 변경할 수 없다. 전화번호 변경은 현재 비밀번호와 새 번호의 인증 증표를 요구하며 기존 계정의 번호와 중복될 수 없다. 중복이면 증표 소비도 롤백한다.

화면에서 실패 시 입력을 유지한다. 인증 대기 중 이메일/전화번호를 변경하면 증표를 버리고, 증표가 만료되면 저장을 차단한다. 비밀번호 보기/숨기기 버튼과 각 입력의 레이블을 분리했다. 민감한 입력·인증 증표는 URL이나 localStorage에 저장하지 않는다.

## 비밀번호 복구

1. `send`에 이메일·전화번호를 보낸다. 형식이 유효하면 등록 여부에 관계없이 같은 형태의 challenge ID/만료/재시도 시간을 반환한다. 서버에서 **등록 이메일 + 현재 전화번호 + 전화 인증 이력**이 모두 일치할 때만 SOLAPI를 호출한다. 불일치는 발송 한도를 소모하는 사용 불가능한 challenge로 저장한다. 잘못된 코드/증표의 검증 오류도 계정 존재 여부에 따라 문구·코드가 달라지지 않도록 처리한다.
2. `verify`는 같은 이메일·전화번호·challenge ID와 6자리 코드를 요구한다. 성공하면 10분 동안 유효한 단회 증표를 반환한다.
3. `reset`은 같은 이메일·전화번호·증표와 8~128자 새 비밀번호를 요구한다. 증표 소비, scrypt 비밀번호 해시 갱신, 인증 버전 증가, 기존 세션 전체 폐기를 같은 SQLite 트랜잭션으로 저장한다. 자동 로그인하지 않고 새 비밀번호로 로그인하도록 안내한다.

인증 범위는 가입/계정별 전화번호 변경/이메일별 비밀번호 복구로 구분한다. 전화번호 변경·복구 증표는 인증 정보의 버전에도 묶인다. 가입 증표로 복구할 수 없고, 비밀번호나 전화번호를 바꾸면 이전에 발급한 복구 증표도 사용할 수 없다. 동시에 같은 증표로 재설정하면 한 건만 성공한다. 비밀번호 검증 뒤 세션 발급 사이에 비밀번호가 바뀐 로그인도 버전 확인으로 거절한다.

기존 문자 제한은 모든 용도에서 공유한다: 코드 5분, 오입력 5회, 발송 간격 60초, 전화번호당 시간당 5회/클라이언트당 20회/전체 100회. 같은 용도로 재발송하면 이전 코드는 무효다. SMS 본문에 회원가입/전화번호 변경/비밀번호 재설정 목적을 표시한다. 현재 비밀번호를 사용하는 민감 작업은 계정당 15분에 10회로 제한하며 시도 기록도 서버 재시작 뒤 유지한다. 복구 HTTP 요청에는 별도 분당 제한도 적용한다.

SOLAPI 설정이 없으면 설정 누락 오류를 표시하며 발송 성공으로 처리하지 않는다. 시드 계정에는 기본 인증 전화번호가 없으므로 로그인 후 프로필에서 먼저 인증해야 SMS 복구가 가능하다. 시드 계정의 비밀번호를 변경/재설정하면 그 계정의 기존 `HALOX_DEMO_PASSWORD` 로그인은 중단되고 개인 비밀번호 해시를 사용한다.

## 세션 저장과 무효화

기존 만료 시각만 있는 서명 토큰을 세션 ID·발급 시각·만료 시각·사용자 ID가 있는 토큰으로 전환했다. 로그인 시 비공개 `account_sessions`에 난수 세션 ID, 계정, 발급/만료 시각, 브라우저/OS 분류를 저장한다. 토큰 원문이나 전체 User-Agent 문자열은 저장하지 않는다. 세션은 12시간이며 계정당 최대 20개다. 한도를 넘으면 오래된 세션부터 종료한다.

모든 사용자 인증 API는 서명 검증에 더해 최신 SQLite의 세션 등록과 계정 존재 여부를 확인한다. `DELETE /api/v1/auth`는 쿠키 삭제와 함께 해당 서버 세션도 삭제한다. ‘다른 세션 모두 로그아웃’은 현재 세션만 남긴다. 전화번호 변경도 현재 세션만 남기며, 비밀번호 변경/복구는 현재 세션까지 모두 종료한다. 복사한 Bearer 토큰도 같은 세션을 참조하므로 함께 차단된다. 종료 전 이미 인증을 마친 요청의 실행을 소급 취소하는 기능은 아니다.

워크스페이스 API 키로 인증하는 `halox-mcp`는 별도 키 인증을 유지한다. 개인 비밀번호 변경이 워크스페이스 API 키를 자동 폐기하지는 않는다. API 키 관리의 나머지 범위는 S11에서 진행한다.

**전환 시 이전 형식의 로그인 쿠키는 더 이상 유효하지 않으므로 한 번 다시 로그인해야 한다.** 운영 데이터·기존 비밀번호·워크스페이스는 유지한다. 세션 등록/민감 작업 시도는 공개 REST 목록 밖의 SQLite 스냅샷에 저장하며, 실제 비밀번호·OTP·증표는 해시로만 보관한다.

- 새 단위 14개: 등록된 세션만 허용/예전 토큰 거절, 서버 재시작 뒤 폐기 유지, 20개 제한·만료·타 계정 세션 차단, 프로필 입력/버전/REST 변경, 현재 비밀번호·동시 로그인 경쟁, 전화 인증 용도 분리·중복 시 롤백·다른 세션 종료, 민감 작업 제한, 불일치 복구의 비발송/같은 응답 형태, 단회 소비·만료·5회 실패·동시 재설정·시드 비밀번호 전환.
- 새 E2E 5개: 이름 수정·실패 입력 보존·다른/현재 세션 로그아웃, 비밀번호 변경과 REST/RPC/함수/집계 API의 폐기 토큰 거절, 문자 전송만 대역으로 사용한 실제 전화 변경·복구, 설정 누락 오류·인증 정보 변경 시 증표 제거·모바일 스크롤.
- 첫 대상 E2E에서 비밀번호 입력의 접근성 이름에 보기 버튼 이름이 합쳐지는 문제가 나와 HTML 레이블 연결을 수정했다. Next.js 경로 알림과 폼 오류를 혼동하지 않도록 테스트의 오류 범위를 main으로 지정했다. 모바일 844px에는 전체 폼이 들어가 스크롤이 필요하지 않았으므로, 600px 높이에서 실제 휠 스크롤을 검증했다. 수정 후 새 E2E 5개를 통과했다.
- Ego Lite에서 프로필 이름 저장/새로고침, 틀린 현재 비밀번호의 입력 보존, 올바른 비밀번호 변경 직후 401과 로그인 이동, 서버 재시작 뒤 새 비밀번호 로그인과 이름 보존을 확인했다. 1428px 데스크톱·390px 모바일에서 가로 넘침이 없고 프로필 영역의 실제 스크롤 위치가 93px 이동했다. 복구의 SOLAPI 미설정 오류도 확인했다.
- 화면 검증은 별도 3110 서버·임시 SQLite·`127.0.0.1` 쿠키로 진행했다. 검증 뒤 TaskSpace 48과 임시 서버를 종료하고 검증 DB를 삭제했다. 개발 계정의 이름/비밀번호와 개발 DB는 변경하지 않았다.
