# API 키·MCP 연결 CRUD

2026-10-24. `/app/settings?tab=api`의 키 관리·API 사용량·API 한도를 실제 서버 자료에 연결했다. 전체 메뉴 목표는 [작업표](full-crud-tasks.md)에 있으며 아직 진행 중이다.

## 발급과 관리

키 이름·만료 시각·16개 권한·분당/일일 한도를 지정해 발급한다. 기본값은 7개 영역의 읽기 권한, 90일 만료, 분당 60회·일일 1,000회다. 만료 없음도 선택할 수 있다. 유효한 미래 만료 시각은 1년 이내이며, 키당 분당 1~600회·일일 1~100,000회로 설정한다. 활성 키 50개·보관 키 500개 한도를 둔다. 같은 워크스페이스의 활성 키 이름은 NFKC·대소문자 정규화로 중복을 거절한다.

새 비밀값은 32바이트 난수로 만들고 `hx_live_` 접두사를 붙인다. 서버에는 SHA-256 해시만 저장하고 전체 비밀값은 발급 응답에서 한 번만 전달한다. 브라우저는 발급 결과 모달의 React 상태에만 보관하며 닫기·새로고침·워크스페이스 전환 후 다시 표시하지 않는다. 자동 복사 실패 시 직접 복사할 수 있다. 목록·REST 조회·다른 로그인 세션에서는 접두사만 표시한다.

이름·권한·만료·한도를 수정하고 키를 영구 폐기할 수 있다. 만료·폐기된 키는 다시 활성화하지 않으며 목록 기록을 삭제할 수 있다. 기록 삭제 후에도 최근 사용량은 보존한다. 화면에서 발생한 실패와 충돌은 입력을 유지하며 성공은 서버 저장 후 표시한다.

발급 요청은 `request_id`로 중복을 방지한다. 응답을 잃고 재요청하면 기존 키 메타데이터와 `secret: null`을 반환하며 다시 발급하지 않는다. 이때 비밀값을 받지 못했다면 해당 키를 폐기하고 새 키를 발급한다. 같은 요청 키의 다른 입력은 409다. 발급 요청 기록에는 비밀값이 없으며, 키 기록을 삭제해도 같은 요청 키로 재생성하지 않는다.

## 관리 API와 권한

세션 인증을 사용하는 `GET /api/v1/api-settings?workspace_id=...`는 키 목록·최근 90일 사용량·공유 한도를 반환한다. 조회는 기타 메뉴 권한이 필요하며, 변경은 전체 메뉴 권한이 있는 워크스페이스 소유자·관리자만 가능하다. 뷰어와 일반 멤버는 조회만 한다.

`POST /api/v1/api-settings`는 `workspace_id`와 다음 명령을 받는다. 모든 응답은 캐시하지 않는다.

| action | 필드 |
|---|---|
| `key-create` | `request_id`, `name`, 선택 `scopes`, `expires_at`, `requests_per_minute`, `requests_per_day` |
| `key-update` | `id`, `expected_revision`, 수정할 이름/권한/만료/한도 |
| `key-revoke` | `id`, `expected_revision` |
| `key-delete` | 만료 또는 폐기한 키의 `id`, `expected_revision` |
| `limits-update` | 공유 한도의 `expected_revision`, `requests_per_minute`, `requests_per_day` |
| `limits-reset` | 공유 한도의 `expected_revision` |

수정과 폐기는 레코드 버전을 비교한다. 이전 RPC 폐기도 버전을 증가시키므로 기존 편집 창은 충돌로 거절한다. 키·공유 한도의 직접 REST 변경은 차단한다. 공개 키 접두사·저장 해시·폐기/만료 키는 인증에 사용할 수 없다. 매 호출 발급자의 현재 멤버십과 전체 관리자 권한을 확인하므로 권한 축소나 멤버 제거 즉시 해당 키도 차단된다. 워크스페이스 삭제 시 키·한도·사용량·발급/작업 요청 기록을 모두 정리한다.

이 HaloX API 키는 OpenAI/SOLAPI의 서비스 비밀키와 별개다. 사용자 로그인 세션이나 비밀키 관리 API에 접근하는 토큰으로 사용할 수 없다.

## 권한과 실제 도구

도구는 키에 연결된 워크스페이스에서만 실행한다. 요청으로 다른 워크스페이스를 지정하거나 임의 테이블·함수를 실행할 수 없다. 도구 목록은 현재 권한에 맞게 필터링하고 실제 실행에서도 다시 검사한다. 기존 키의 `scopes`가 없는 경우에만 읽기 권한으로 호환하며, 알 수 없는 권한 문자열은 인증을 거절한다.

| 영역 | 읽기 | 쓰기 | 별도 삭제 |
|---|---|---|---|
| 워크스페이스 | 정보·플랜 사용량 | 이름·설명·브랜드·도메인·슬러그 | 소유자가 발급한 키만 가능, 현재 이름·버전 확인 |
| GEO | 저장 AVI·실행 지표 | 기존 프롬프트 즉시 실행 | 없음 |
| 프롬프트/원본 | 질문 목록·실행 답변·인용 | 질문 등록·수정·세트/활성 상태 | 질문과 과거 실행 연쇄 삭제 |
| SEO | 키워드·SERP·저장 GSC/GA4 | 등록/수집·재수집·수정/세트 연결 | 키워드와 측정 이력 연쇄 삭제 |
| 사이트 진단 | 진단 목록·페이지·이슈 | 없음 | 없음 |
| 콘텐츠 | 작업·본문 버전 | 직접 작성·새 본문 버전 저장 | 없음 |
| 자료실 | 본문·출처·근거 | 텍스트 자료 등록·수정 | 없음 |

쓰기와 삭제는 각각 명시적으로 선택한다. 도구의 필드·타입·범위를 검증하며 변경 시 최신 버전 또는 `updated_at`이 필요하다. 키워드·프롬프트 삭제는 `confirm: true`도 요구한다. 기존 도메인 검증·생성 사용량·브랜드 재분류·연쇄 삭제를 재사용한다. GEO 실행 결과는 지표와 실행 ID만 반환하고 답변 원문은 프롬프트 읽기 권한에서 조회한다.

쓰기 도구는 `request_id`가 필수다. 같은 키·요청 ID·정규화 입력은 이전 결과를 반환하고, 다른 입력은 409로 거절한다. 키를 삭제하면 해당 작업 응답 기록도 정리한다. 실패한 도구는 부분 변경과 사용량 예약을 롤백하되 API 요청 실패 집계는 보존한다. 외부 수집은 현재 데모 Provider이며 화면과 도구 설명에 명시한다. 실제 검색·AI Provider 연동 완료를 의미하지 않는다.

## MCP와 HTTP API

`POST /api/v1/mcp`는 `Authorization: Bearer <API_KEY>` 또는 `x-api-key`로 인증한다. `initialize`, `notifications/initialized`, `notifications/cancelled`, `ping`, `tools/list`, `tools/call`을 지원한다. 프로토콜 버전은 `2025-11-25`, `2025-06-18`, `2025-03-26`을 협상한다. 상태 없는 JSON 응답 방식이며 서버 시작 SSE 스트림은 제공하지 않으므로 GET/DELETE는 405다. Origin이 있으면 현재 서버와 같은 출처인지 검사하고 다르면 403을 반환한다. 알림 수락은 본문 없는 202, 도구 실행 실패는 MCP `isError` 결과로 전달한다. 인증·범위·요청 형식·한도 오류는 별도의 HTTP 오류다.

구현 시 [MCP HTTP 전송](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [초기화](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [도구 규약](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)을 확인했다. HTTP 계약을 검증했으며 Claude·Codex 등의 실제 클라이언트 연결까지 검증했다는 뜻은 아니다. 원격 클라이언트에는 접근 가능한 HTTPS 배포 주소가 필요하다. 화면은 현재 사이트 주소로 연결 경로를 안내하며 실제 비밀값을 예시 코드에 삽입하지 않는다.

`POST /api/v1/public/<tool>`은 같은 헤더 인증과 권한·한도·중복 방지를 사용하는 일반 JSON API다. 본문은 도구 인수 객체이며 성공 응답은 도구의 데이터다. 예: `list_keywords`에 `{"limit":20,"offset":0}`. MCP의 `tools/list` 응답에 각 도구의 설명과 입력 스키마가 있다. 기존 `/api/v1/functions/halox-mcp` 경로도 같은 실행기로 연결했으며 이 호환 경로에서만 기존 본문 `api_key`를 받는다. 새 경로는 본문의 키로 인증하지 않는다.

## 사용량과 한도

키별 한도와 워크스페이스 공유 한도를 모두 검사한다. 공유 기본값은 분당 300회·일일 10,000회이며 수정·초기화할 수 있다. 한도를 낮추거나 높여도 이미 사용한 요청 수는 유지한다. 일일 경계는 UTC 00:00, 분당 경계는 UTC 분 단위다. 한도 초과는 429와 `Retry-After`를 반환한다.

인증된 요청의 성공·실패·권한 거절·호출 도구를 일별로 집계한다. 한도 초과 요청은 별도 횟수로 기록하고 실행 요청 수에는 합산하지 않는다. 초기화/도구 목록/재시도도 요청 수에 포함한다. 인증되지 않은 요청은 키 사용량에 기록하지 않는다. 사용량에는 키 ID·이름·접두사·시각과 숫자만 있으며 요청 본문·비밀값은 저장하지 않는다. 최근 90일 집계를 조회한다.

SQLite 쓰기 트랜잭션에서 인증 재확인·한도 소비·도구 실행·중복 방지·결과 집계를 처리한다. 복수 프로세스와 서버 재시작에도 카운터와 변경이 유지된다. 현재는 로컬/단일 서버 저장 방식이며 분산 배포·대규모 호출 성능 검증은 포함하지 않는다. 이 API 한도는 기존 플랜의 키워드/프롬프트 생성 사용량과 별개다.

- 이후 전체 E2E에서 기존 권한 테스트 2개가 SQLite 잠금으로 실패했다(86/88). 오류 코드만 수집한 반복 진단에서 `261 SQLITE_BUSY_RECOVERY`를 재현했다(14/15). 기존 재시도는 기본 코드 5/6만 인식했다. [SQLite 공식 오류 코드](https://www.sqlite.org/rescode.html#busy_recovery)에 따라 하위 8비트의 기본 코드로 분류하도록 수정했다. 변경 전 회귀 테스트 7/8, 변경 후 8/8로 확인했다. 비잠금 I/O 오류는 즉시 실패하며, 잠금 재시도 중 도메인 작업을 중복 실행하지 않는다. 수정 후 동일 권한 E2E를 5회 반복하여 15/15 통과했다.
- 전체 단위 **266/266**, 백엔드 계약 **22/22**, 타입 검사·프로덕션 빌드 통과. 최종 전체 E2E **88/88 (2.6분)** 통과. 경로 **363개**에서 누락·실패·중복·자산 누락 0개, 원본 404 73개.
- Ego Lite TaskSpace 53과 별도 3110 서버·임시 SQLite에서 키 발급, HTTP 읽기 성공/쓰기 권한 거절, MCP 도구 목록을 실행했다. 호출 3회/성공 2회/권한 거절 1회가 서버 재시작 후 유지됐다. 목록에는 접두사만 표시하며 비밀값은 다시 표시하지 않았다. 화면 폐기 후 같은 키 HTTP 호출은 즉시 401이었고, 키 기록 삭제 후에도 사용량은 유지됐다. 1428×747 화면의 문서 너비는 1428px, 390×600 화면의 문서 너비는 390px이며 본문 스크롤 628px를 확인했다. TaskSpace 53과 검증 서버를 종료하고 임시 DB·자격증명·비밀값 파일을 삭제했다.
