# GEO 프롬프트 CRUD 및 예약 실행

2026-10-23 구현. `/app/geo`, `/app/geo/prompts`, `/app/geo/prompts/:id`는 수집 HTML의 본문 대신 서버 레코드를 표시한다. 공통 사이드바와 헤더는 유지한다.

## 화면과 데이터

| 화면 | 모델 | 동작 |
|---|---|---|
| 프롬프트 목록 | `geo_prompts`, `geo_prompt_sets` | 생성·조회·편집·삭제, 질문/세트/엔진/상태 필터, 정렬·12개 단위 페이지·선택 삭제·CSV |
| 프롬프트 세트 | `geo_prompt_sets` | 이름·설명·브랜드 도메인·기본 엔진·기본 세트·활성 상태·예약 시간 CRUD |
| 태그 | `workspace_tags`, `workspace_tag_groups`, `geo_prompt_tag_assignments` | 키워드 화면과 같은 태그/그룹 CRUD, 질문 편집에서 연결·해제 |
| 동적 상세 | `geo_prompt_runs`, `geo_answers_raw`, `geo_citations`, `geo_run_metrics` | 질문별/엔진별 실행, 답변 원문·인용 링크·과거 질문·실패 기록, 실행 이력 삭제 |
| AI 대화 개요 | 위 데이터의 최신 실행 | 실제 등록 수·완료 실행의 언급/인용 비율·최근 이력, 빈 상태 |

현재 엔진은 ChatGPT·Gemini·Perplexity·Claude를 구분하는 **결정적 데모 Provider**다. 외부 LLM API를 호출하지 않으며 화면에도 모의 결과임을 표시한다. 비용은 0으로 저장한다. 브랜드 도메인이 없으면 자사 언급/인용으로 계산하지 않는다. 질문·언어·국가를 수정해도 과거 실행의 질문과 원문은 보존하고 현재 지표에서는 제외한다.

세트를 삭제하면 질문은 미분류로 남고 예약이 해제된다. 질문을 삭제하면 실행·답변·인용·지표·태그/키워드 연결을 정리한다. 실행 하나를 삭제하면 그 실행의 결과만 정리한다.

## API 및 저장

- `GET /api/v1/prompts?workspace_id=…`: 워크스페이스 소속을 확인하고 필요한 11개 테이블을 동일 SQLite 스냅샷에서 읽는다. 다른 워크스페이스는 403, 비로그인은 401이다.
- `POST /api/v1/functions/geo-run`: 신규 질문과 선택한 1~4개 엔진 실행을 하나의 트랜잭션으로 저장한다. 질문 생성당 `prompt_create` 1개만 차감한다. 재실행은 추가 생성 차감이 없다.
- `POST /api/v1/functions/geo-save`: 질문 수정과 태그 변경을 함께 저장한다. `updated_at`으로 오래된 편집을 차단한다.
- 세트/태그/일시정지/삭제는 기존 REST를 사용한다. 공개 REST로 질문을 새로 만들거나 답변/측정값을 조작할 수 없다.
- 새 질문의 엔진 실행이 실패하면 질문·부분 결과·사용량 예약이 모두 롤백된다. 기존 질문의 실행 실패는 이력에 남고 화면에 실패를 표시한다.
- 이미 사용한 생성 요청 키는 재사용을 거부한다. 삭제한 질문에도 같은 키를 다시 쓸 수 없다. 응답 재생을 포함한 범용 요청 중복 처리는 F10의 후속 범위다.
- 사용량 예약·확정·해제 RPC는 공개 HTTP 호출을 거부한다. 실제 생성 함수가 서버 내부에서 처리한다.

공통 `WorkspaceProvider`가 로그인 사용자·워크스페이스·플랜을 `/api/v1/auth` 한 번으로 조회한다. `ClonePage`는 이 세션을 재사용한다. 워크스페이스 관리 화면도 `GET /api/v1/workspaces` 한 번으로 소속·플랜·항목 수를 읽는다. 응답은 `private, no-store`이며 요청 제한을 늘리지 않았다.

## 예약 실행

Next.js Node 서버의 `instrumentation.ts`가 주기 실행기를 시작한다. 기본 확인 주기는 30초이며 활성 세트의 `next_run_at`이 지났으면 그 세트의 활성 질문을 실행한다. 일시정지/삭제/비활성 질문은 건너뛴다.

- 매일 지정한 **한국시간 0~23시**를 UTC 시각으로 저장한다. 끄면 `next_run_at`이 null이 된다.
- 예약 시각 이동과 모든 실행 결과는 동일 SQLite 작성 잠금 아래 커밋된다. 복수 실행기가 동시에 확인해도 재조회하므로 같은 회차를 중복 저장하지 않는다.
- 서버가 꺼져 있는 동안 실행하지 않는다. 다시 시작하면 밀린 예약을 한 회차 처리한 다음 다음 날로 이동한다. 과거 모든 날짜를 재생하지 않는다.
- Provider 실패는 해당 회차의 실패 이력으로 남고 다음 예약으로 넘어간다. 저장소 실패는 다음 확인 주기에 재시도한다.
- `HALOX_DISABLE_SCHEDULER=1`로 실행기를 끈다. `HALOX_SCHEDULER_INTERVAL_MS`로 확인 주기를 바꿀 수 있다(최소 1초). 운영은 기본값을 권장한다.

영속 디스크가 있는 장기 실행 Node 서버 범위다. 외부 cron/분산 작업 큐/진행 중 취소는 아직 구현하지 않았다. 실 LLM 연동 시 긴 외부 호출을 작성 잠금 밖의 작업 큐로 옮겨야 한다.
