# 계정 탈퇴와 30일 복원

2026-10-24. S13의 탈퇴 요청, 재인증 후 취소·복원, 유예 만료 후 정리를 구현했다. 워크스페이스 설정 하단과 내 프로필에서 진입하며, 로그아웃 후에는 `/app/restore-account`에서 본인 계정을 복원한다. 전체 메뉴의 남은 작업은 [작업표](full-crud-tasks.md)를 따른다.

## 데이터와 API

- 비공개 `account_deletions`: 사용자 ID, active/pending, revision, 요청 시각, 삭제 가능 시각, 복원 시각. REST 테이블에 노출하지 않는다.
- 비공개 `account_deletion_requests`: 계정별 처리한 요청 키. 복원 후 같은 키를 재사용해 다시 탈퇴시키지 못한다. 계정 최종 삭제 시 함께 제거한다.
- 비공개 `account_restore_attempts`: 이메일·클라이언트 해시와 시각. 복원 조회/확정의 성공·실패를 포함해 이메일당 15분 10회, 클라이언트당 100회로 제한한다. 서버 재시작으로 제한을 우회하지 못한다.
- `GET /api/v1/account/deletion`: 현재 세션의 계정만 조회한다. 삭제 대상 소유 워크스페이스, 다른 멤버 수, 미확인 외부 작업, 미정산 추천 보상, 상태 버전, 확인 대상 해시를 반환한다.
- `POST /api/v1/account/deletion`: 현재 비밀번호, 계정 이메일, `계정 탈퇴` 문구, 안내 동의, 버전/확인 대상 해시, 새 요청 키가 필요하다. 다른 계정 ID를 받아 처리하지 않는다.
- `POST /api/v1/auth/restore`: `inspect`/`restore` 모두 가입 이메일과 비밀번호를 검증한다. 조회는 복원 기한·버전만 반환하며 계정을 활성화하지 않는다. 확정에는 최신 버전과 명시적 동의가 필요하다.
- 과거 `cancel_account_deletion` RPC의 무조건 성공 응답을 제거했다. 직접 RPC와 `rpc-cache` 모두 거절하고 재인증 복원 API를 사용한다. 수집된 원본 RPC 스키마는 관측 자료로 남긴다.

## 요청과 소유권 정책

선택한 워크스페이스 하나가 아닌 **계정과 소유한 모든 워크스페이스**가 대상이다. 사용자에게 삭제 대상 목록을 보여준다. 본인 소유 워크스페이스에 다른 멤버가 있으면 요청을 거절하고 멤버 정리를 안내한다. 소유권 자동 이전이나 다른 계정의 자료 삭제는 수행하지 않는다. 다른 사람의 워크스페이스에 속한 뷰어도 내 프로필에서 본인 계정을 탈퇴할 수 있다.

진행 중/결과 미확인 OpenAI 번역·WordPress 게시가 있거나 미정산 추천 보상이 있으면 먼저 정리해야 한다. 비밀번호 검증 뒤 같은 저장 트랜잭션에서 인증 버전·공유 멤버·미확인 작업·보상 잔액·확인 대상 해시를 다시 검사한다. 다른 창에서 멤버가 추가되면 409로 거절하고 화면 입력을 보존한다.

요청 성공 시 한 트랜잭션에서 다음을 처리한다.

1. 계정을 pending으로 바꾸고 서버 기준 정확히 30×24시간 후를 복원 마감으로 저장한다. 계정 인증 버전을 올리고 모든 로그인 세션을 폐기한다.
2. 소유 워크스페이스의 GEO/감시/리포트 예약을 끄고 진단·사이트맵 보완을 취소한다. 작업 큐를 제거해 늦게 도착한 수집 응답도 반영하지 않는다. 미확정 사용량 예약은 해제하고 이미 확정한 사용량은 유지한다.
3. 소유 워크스페이스의 대기 초대와 토큰을 취소한다. 발급한 API 키와 추천 링크를 영구 폐기한다.
4. 소유 워크스페이스에 저장한 WordPress 암호화 자격증명을 삭제하고 연결을 미검증 상태로 바꾼다. 이미 원격에 게시한 글은 삭제하지 않는다. 원격 WordPress 애플리케이션 비밀번호 자체의 폐기는 사용자가 WordPress에서 진행한다.

로그인 쿠키·복사된 Bearer 토큰, API 키, 멤버십 조회, 공개 REST와 서버 데이터 변경은 pending 계정을 거절한다. 탈퇴 직전 인증한 요청이 늦게 쓰기를 수행해도 자료를 새로 만들지 못한다. 이메일과 전화번호는 유예 기간 중 다른 신규 계정이 가져갈 수 없다.

## 복원과 최종 삭제

현재 비밀번호를 잊은 사용자는 기존 이메일·등록 전화번호의 SOLAPI 인증으로 비밀번호를 재설정할 수 있다. 유예 기간 중 비밀번호 재설정은 계정을 활성화하지 않으며 별도 복원 확정이 필요하다. 복원하면 계정·소유 자료·남아 있는 멤버십을 다시 사용할 수 있다. 다른 소유자가 유예 기간 중 제거한 멤버십은 재생성하지 않는다. 인증 버전은 다시 증가하며 예전 세션은 복구하지 않는다.

폐기한 API 키·추천 링크·대기 초대·WordPress 연결 비밀번호와 중단한 예약/진단은 복원해도 자동으로 되살리지 않는다. 화면에서 다시 설정하도록 안내한다.

서버 시작 시와 60초 주기로 정리 작업을 실행한다. 복원과 정리는 SQLite의 동일한 쓰기 잠금 아래 직렬화한다. 마감 시각 **미만**에만 복원할 수 있고, 정확한 마감 시각부터 410을 반환한다. 서버가 중단됐더라도 마감 후 복원은 불가능하며 다시 시작한 정리 작업이 만료 계정을 처리한다. 복수 작업자가 실행되어도 정리는 한 번만 적용한다.

최종 삭제는 프로필·인증 해시·세션·탈퇴 요청 기록, 소유 워크스페이스와 소속 테이블/원본/파일/자격증명/큐, 다른 워크스페이스의 멤버십·개인 대시보드 설정, 개인 연락처·피드백/답변·대기 추천 초대를 제거한다. 다른 소유자의 업무 내용은 유지하고 계정 참조 필드를 비운다. 확정된 추천 가입/보상은 탈퇴 계정의 이름·이메일·가입자/소유자 ID를 제거해 보존하며 폐기 코드 문자열은 재사용 방지용으로 남긴다.

정리는 현재 런타임 저장소의 논리적 삭제다. 외부 게시물, 별도로 만든 백업·내보낸 파일, 다른 사용자의 업무 본문에 직접 입력한 이름까지 삭제했다고 주장하지 않는다. 백업/복구 정책은 F10/Q03, 실 결제 해지·정산 연계는 S06/S14, Google 연결 해제는 S09의 후속 범위다. `HALOX_DISABLE_ACCOUNT_DELETION_WORKER=1`은 격리 검증용이며 운영에서는 정리 작업을 계속 실행해야 한다. 작업자가 꺼져 있어도 복원 마감은 서버에서 집행한다.

## 검증

단위 8개는 재인증/확인 입력/공유 멤버 충돌, 모든 세션·키 폐기와 예약/큐 중단, 재개방과 복원 경계/요청 재사용/인증 경합, 전체 소유 데이터 정리와 다른 워크스페이스 보존/익명 원장, 외부 작업·미정산 보상 차단, 유예 기간의 전화 기반 비밀번호 복구와 복원 제한, 실제 정리 작업자의 재개방 후 처리를 검증한다. 레거시 RPC/캐시 우회 거절과 비밀번호 검증 중 마감이 지난 경우 저장 직전 거절도 포함한다.

E2E 4개는 두 소유 워크스페이스의 탈퇴/503·비밀번호 실패 입력 보존/기존 세션 폐기/명시적 복원/재로그인, 공유 멤버 사전 차단과 검토 후 충돌, 만료 복원 거절과 정리 후 로그인 실패, 소유 공간 없는 뷰어의 본인 탈퇴 및 모바일 복원 확인 초기화를 검사한다. 전체 E2E 첫 실행의 선택자 실패는 Next.js 화면 전환 알림까지 `alert`로 선택한 테스트 문제였으며 복원 화면 안으로 범위를 한정했다.

Ego Lite의 격리 계정·SQLite에서 워크스페이스 설정 → 탈퇴 → 서버 재시작 → 복원 기한 확인 → 명시적 복원 → 새 세션 로그인과 프로필/소유 워크스페이스 보존을 확인했다. 모바일 390×600에서 가로 너비 390px, 본문 스크롤 118px을 확인했다. 비밀번호는 가린 상태로 캡처했고 실제 사용자 계정이나 외부 Provider는 사용하지 않았다.
