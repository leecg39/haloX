# SEO/GEO 분석과 기회 후보 CRUD

2026-10-23. P03 `/app/seo/insights`, P05 `/app/geo/analysis`, P06 `/app/gap`를 저장 데이터 기반 화면으로 전환했다. 전체 메뉴의 남은 작업은 [작업표](full-crud-tasks.md)에 유지한다.

## 분석 조건과 집계

`GET /api/v1/analyses?workspace_id=...&kind=seo|geo&filters=JSON`은 세션·워크스페이스 권한을 확인하고 `private, no-store`로 반환한다. 날짜는 UTC의 양 끝 날짜를 포함하며 최대 366일, 기본 28일이다. 엔진/세트/태그/검색어/언어/국가/추적 상태를 적용하고 SEO는 비교 도메인도 지정할 수 있다. 직전 비교 구간은 같은 길이다. 삭제한 세트·태그를 지정하면 오류를 반환하여 필터가 조용히 풀리지 않게 한다.

- SEO는 기간 내 키워드·엔진별 최신 표본으로 Top 10, 순위, AIO, 출처를 집계한다. 평균 순위는 실제 노출 순위만, Top 10 비율은 순위를 측정한 표본을 분모로 사용한다. 도메인은 정확한 호스트 또는 하위 도메인만 일치한다. 검색량/난이도는 수집 당시 값을 사용하며, 값이 없던 과거 표본을 현재 값으로 채우지 않는다.
- GEO는 해당 기간의 완료 실행을 모두 집계한다. 같은 질문의 반복 실행도 각각 표본이다. 멘션·인용 값이 없는 실행과 자사 도메인이 설정되지 않은 신규 실행은 미측정으로 처리한다. 엔진별 표·직전 기간 비교·일별 추이·인용 출처·질문별 최신 엔진 매트릭스를 제공한다.
- 문구·언어·국가가 현재 항목과 다른 자료, 삭제 항목, 미완료 실행은 집계에서 제외한다. 출처는 유효한 HTTP(S) URL만 표시하며 같은 표본의 중복 URL을 제거한다. GEO 자사/경쟁사 구분은 수집 당시 분류를 보존한다.
- 일별 SVG 그래프에는 지표 선택, 날짜/값 설명, 대체 수치 표가 있다. 표는 페이지 이동과 CSV를 지원한다. 수집 근거에서 실제 저장된 답변·출처·Provider를 확인할 수 있다.

`saved_analyses`는 이름·종류·조건·메모·revision을 저장한다. `analysis-create/update/delete` 명령으로 생성·수정·삭제하고, 재조회 시 조건으로 현재 저장 자료를 다시 집계한다. 측정값을 고정 보관하는 기능은 아니다. 이름 중복, 조건 형식/참조, 200개 제한을 검사하며 오래된 revision은 409를 반환한다. UI는 오류 시 입력을 유지한다.

## 기회 후보와 판단 이력

`GET /api/v1/gaps?workspace_id=...&filters=JSON`은 키워드와 연결된 질문의 최신 측정 자료를 결합한다. 검색 엔진 중 자사 Top 10이 있으면 검색 노출, 연결 질문·엔진 중 자사 인용이 있으면 AI 노출이다. 검색/AI 양쪽에 측정 자료가 있어야 모두 노출·검색만·AI만·모두 미노출을 판정한다. 자료가 부족하면 별도 유형으로 표시한다.

| 저장 모델 | 명령과 동작 |
|---|---|
| `geo_prompt_candidates` | `candidate-create/update/delete`: 키워드/질문 문구·언어·국가·우선순위·메모 관리 |
| 후보 생성 근거 | `candidate-generate`: 선택 키워드의 최신 일치 SERP에 저장된 연관 검색어/PAA로 최대 20개 생성. 원본/Provider/수집일 보존 |
| 후보 상태 | `candidate-status`: 검토 대기↔보류. 채택 후에는 문구/유형/언어/국가 변경을 차단 |
| 실제 등록 | `candidate-adopt`: 기존 동일 문구/언어/국가 항목 재사용 또는 기존 키워드/GEO 명령으로 생성·데모 수집. 원본 키워드와 새 질문 연결 |
| `opportunity_decisions` | 채택/보류/재개 당시 후보 스냅샷 저장. `decision-update/delete`로 메모 수정·이력 삭제 |

채택과 목적 항목 생성·사용량·연결·판단 기록은 하나의 저장 트랜잭션이다. 이미 채택한 후보를 다시 요청해도 등록이나 과금이 반복되지 않는다. 목적 항목을 나중에 삭제해도 재요청으로 재생성하지 않는다. 후보 삭제 시 판단 기록을 정리하며 이미 생성된 실제 항목은 유지한다. 동일 유형/문구/언어/국가 후보 중복과 500개 제한을 검사한다.

워크스페이스별 조회·참조·쓰기를 검증하며 공개 REST에서 분석 조건·후보·판단 기록을 직접 조작하지 못하게 한다. 워크스페이스 삭제 시 관련 자료도 정리한다.

## 검증

신규 단위 테스트 18개는 날짜/분모/도메인/결측값, 필터와 원본 정합성, 저장 조건 CRUD·재시작·revision·격리, 후보 상태·중복·채택 원자성·실패 롤백을 검증한다. 신규 E2E 5개는 저장→편집→재조회→삭제, 근거·CSV, 후보 채택→실제 상세 이동, 실패 입력 보존·권한·모바일을 검증한다.

Ego Lite에서도 저장 조건 재조회, 후보 생성/메모/우선순위 수정/채택/실제 질문 이동, 390px 화면의 가로 넘침 없음과 실제 휠 스크롤을 확인했다. 검증용 자료만 별도 워크스페이스에 만들고 검증 후 삭제했다. ## 남은 범위

현재 수집 Provider에 데모 결과가 포함되므로 실제 시장 성과 검증을 의미하지 않는다. 제품별 인용이나 Fan-out 질문처럼 원본 수집 계약에 없는 별도 측정 자료는 만들지 않는다. 콘텐츠 기회는 저장한 목표 키워드의 문구 일치로만 연결하며 콘텐츠 품질·게시 상태나 예상 성과를 추정하지 않는다. 분석 화면의 기존 정적 수치를 실측처럼 보존하지 않았다. 향후 실제 수집 Provider가 연결되면 같은 집계 계약으로 검증해야 한다.
