# 사이트 진단 대상·실행·결과 CRUD

2026-10-23. P08 `/app/site-audit`와 `/app/site-audit/:id`를 서버 저장소에 연결했다. 진단 대상을 등록하고 공개 HTML을 실제로 수집하며, 당시 수집 범위·페이지별 근거·조치 메모를 보관한다. 전체 메뉴 진행 상태는 [작업표](full-crud-tasks.md)를 따른다.

## 사용자 기능

- 대상 이름·시작 URL·최대 페이지·탐색 깊이·포함/제외 경로·메모를 생성, 조회, 수정, 삭제한다. 이름은 워크스페이스 안에서 중복될 수 없다.
- 저장한 대상에서 진단을 시작하고 대기/수집 중에 취소한다. 완료·실패·취소 이력은 이름과 메모 수정, 동일 범위 재실행, 삭제가 가능하다. 재실행은 새 사용량을 소비하는 별도 진단이다.
- 이력 검색·상태 필터·페이지네이션, 상세의 페이지/점검 항목 탭·검색·심각도/조치 필터·CSV를 제공한다. CSV는 현재 필터 결과 전체를 내려받으며 수식 입력을 무력화한다.
- 점검 항목의 조치 여부와 메모를 수정한다. 원본 측정값과 점수는 바뀌지 않는다. 사이트를 수정한 뒤 새 진단을 실행해야 새 측정 결과가 생긴다.
- 모든 조회·명령은 선택한 워크스페이스의 멤버십을 검사한다. 다른 워크스페이스의 ID를 제출해도 접근할 수 없다. 저장 충돌은 409로 거절하고 실패한 입력을 보존한다.

## 모델과 API

| 위치 | 저장 내용 |
|---|---|
| `site_audit_targets` | 이름·URL·범위·페이지/깊이 한도·메모·revision |
| `site_audit_scans` | 설정 스냅샷·실행 상태·진행 수·관측 점수·사용량·메모·재실행 참조 |
| `site_audit_pages` | 요청/최종 URL·HTTP 상태·수집 상태·HTML 관측값·링크·점수 |
| `site_audit_issues` | 실제 해당 페이지 ID·근거·개선 안내·조치 상태·메모·revision |
| 비공개 `audit_work` | 남은 URL/깊이·방문 URL·robots 정책·다음 실행 시각·작업 점유 토큰 |
| 비공개 `audit_requests` | 사용자/워크스페이스/요청 키/요청 지문/실행 ID |
| 비공개 `audit_hosts` | 출처별 공유 실행 점유·다음 요청 가능 시각 |

`GET /api/v1/site-audit?workspace_id=...`는 네 공개 테이블의 같은 시점 자료를 반환한다. `audit-target-create/update/delete`, `site-audit-start`(별칭 `site-audit`), `site-audit-rerun/cancel/update/delete`, `site-audit-issue-update`를 전용 명령으로 사용한다. 수정/삭제와 실행 대상 선택은 `expected_revision`, 실행/재실행은 `idempotency_key`가 필요하다. 취소는 진행 중 revision이 변하므로 불변 실행 ID만 사용한다.

공개 REST로 대상·실행·측정값을 직접 변경할 수 없다. `site_audit_links_summary` RPC는 선택한 실행의 저장된 페이지/링크만 집계한다. 고아 페이지 탐지는 수행하지 않으며 `orphan_detection=not_measured`를 반환한다. 이전 데모 진단은 화면에서 명시하고 실제 점수로 표시하지 않는다.

대상 삭제 시 종료된 이력의 대상 참조만 해제하고 설정 스냅샷을 유지한다. 이력 삭제는 페이지·점검 항목을 함께 삭제하고 다른 이력의 재실행 참조를 해제한다. 요청 키 기록은 남아 같은 키가 새 실행을 만들지 못한다. 진행 중인 대상/워크스페이스는 먼저 취소해야 삭제할 수 있다. 워크스페이스 삭제 시 공개 자료와 비공개 작업/요청 기록을 정리한다.

## 수집과 진단 범위

시작 URL에서 같은 출처(origin)의 링크를 너비 우선으로 탐색한다. 최대 100페이지, 깊이 5, 포함/제외 경로 각각 30개다. 경로는 접두어 구간으로 비교한다(`/docs`는 `/docs`와 하위 경로에 적용). 쿼리 URL·외부 출처·nofollow·범위 밖·robots 차단 경로를 탐색하지 않는다. 페이지당 처음 500개 앵커 안에서 지원하는 링크만 보관한다. Sitemap 탐색이나 JavaScript 실행은 수행하지 않는다.

실제 HTML의 title·검색 설명·h1·lang·canonical·색인 제한·이미지 alt 누락·JSON-LD 구문을 검사한다. 빈 alt는 장식 이미지로 허용한다. JSON-LD는 문법만 확인하며 스키마 유효성은 별도다. Lighthouse 성능·검색 순위·AI 노출/준비도는 측정하지 않는다. HTML 점수는 페이지마다 `max(0, 100 - 오류×30 - 주의×10 - 안내×2)`이며 분석에 성공한 HTML 페이지들의 평균을 반올림한다. 실패/제외 페이지 수는 별도로 표시하고 점수에 넣지 않는다.

HTTP(S) 표준 포트만 사용한다. URL의 자격증명·사설 주소·localhost를 거절하고, DNS의 모든 응답을 검사한 뒤 검증한 주소를 소켓에 고정한다. 리디렉션은 최대 3회이며 각 목적지에 동일 검사를 수행한다. 출처나 범위를 벗어나는 리디렉션도 거절하므로 처음부터 실제 최종 출처의 URL을 등록해야 한다. TLS 인증서를 검증하며 쿠키/인증 헤더를 보내지 않는다. 요청 전체 제한 8초(DNS 포함), 헤더 16KiB, 본문 2MiB, UTF-8 HTML/텍스트를 지원한다. 서버가 identity 요청에도 압축 응답을 강제하면 오류로 남긴다.

`HaloXAudit/1.0` 사용자 에이전트를 사용한다. 첫 작업은 robots.txt 확인이며 다음 작업부터 페이지를 요청한다. robots는 512KiB 이하 text/plain만 허용한다. 429/5xx/네트워크/정책 해석 오류는 진단 실패로 기록하고, 그 외 4xx는 정책 없음으로 처리한다. robots의 crawl-delay와 최소 1초 간격을 지키며 여러 워크스페이스와 실행기가 같은 출처의 간격을 공유한다. 파서는 [robots-parser](https://github.com/samclarke/robots-parser) 3.0.1이다.

## 실행·복구·사용량

Node 서버 시작 시 `src/instrumentation.ts`가 실행기를 시작한다. 서버 재시작 후에도 SQLite의 대기 작업과 체크포인트에서 계속한다. 작업마다 45초 점유를 저장하고, 동일 페이지의 반복 중단은 최대 3번 점유 후 실패로 종료한다. 네트워크 요청 중에는 SQLite 쓰기 잠금을 잡지 않는다. 중복 실행기는 같은 작업/출처를 동시에 가져가지 못한다.

작업 생성 시 진단 사용량 1회를 예약하고 첫 작업을 시작할 때 확정한다. 시작 전 취소는 예약을 반환한다. 시작 후 취소·네트워크 실패·robots 차단은 이미 사용한 1회와 부분 결과를 보존한다. 취소 후 늦게 도착한 응답은 저장하지 않는다. 같은 요청 키/내용은 재시작 후에도 같은 이력을 반환하며 다른 내용에 재사용하면 거절한다.

`HALOX_DISABLE_AUDIT_WORKER=1`로 실행기를 멈출 수 있다. 대기 작업은 저장되어 남고 GEO 예약 실행 설정과 독립적이다. 환경변수나 실행기 등록 코드를 바꾼 뒤 서버를 재시작한다. 이 구현은 영속 로컬 디스크를 사용하는 상시 Node 서버용이며 서버리스의 요청 밖 실행을 보장하지 않는다. 범용 작업 큐와 다른 도메인 전환은 F10에 남아 있다.

## 검증

- 단위 **138/138**, 백엔드 계약 **22/22**, 전체 E2E **47/47**, 타입 검사·프로덕션 빌드 통과. 범위 인코딩 검증 추가 후 진단 단위 **9/9**도 재확인했다.
- 새 단위 9개: 범위/제한, 실제 HTML 파싱·페이지별 근거, 영속성/요청 중복, 취소/사용량, 동시 실행/늦은 응답, 점유 복구/robots 간격, HTTP/DNS 차단, 권한/연쇄 삭제를 확인한다.
- 새 E2E 3개: 대상 CRUD·실패 입력 보존·충돌·격리, 큐→페이지/점검 결과→메모/조치→재실행/삭제, 모바일에서 부분 수집 취소·새로고침 보존을 검증한다. HTTP 명령과 SQLite 실행기는 실제 코드이며 공개 사이트 응답만 fixture다. 자동 E2E에서는 기본 실행기를 끄고 테스트가 같은 실행기를 직접 호출한다.
- Ego Lite에서 별도 QA 워크스페이스에 `https://example.com/`를 등록했다. 실행이 대기 중인 상태에서 개발 서버를 재시작하자 자동으로 수집을 이어가 HTTP 200, HTML 1페이지, 관측 점수 78, 점검 항목 3개를 저장했다. 당시 HTML 응답은 577바이트였다. 이후 QA 워크스페이스를 삭제했다.
- 데스크톱 1428×900, 모바일 390×844에서 확인했고 모바일 문서 너비는 390px이었다. [데스크톱](evidence/2026-10-23-site-audit.png), [모바일](evidence/2026-10-23-site-audit-mobile.png), [실제 저장 결과](evidence/2026-10-23-site-audit-live.json).

robots-parser 추가 후 의존성 검사에서 기존 Playwright 1.52의 알려진 브라우저 다운로드 취약점이 발견되어 패치된 최소 버전 1.55.1로 올렸다. `npm audit` 결과 취약점 0개였고 해당 버전으로 전체 E2E를 통과했다.
