# 대시보드·모니터링·리포트 CRUD

2026-10-23. 전체 메뉴 작업표의 P01/P12/P13 구현 범위. SQLite 영속 저장소와 현재 선택한 워크스페이스를 사용한다. 전체 메뉴 구현 완료를 뜻하지 않는다.

## 화면과 모델

| 화면 | 저장 모델 | 기능 |
|---|---|---|
| `/app` | `dashboard_preferences`, 기존 검색·GEO·진단 자료 | 실제 등록 개수/지표/표본, 최근 7·28·90일 설정, 패널 선택·순서, 표본 정렬, 설정 초기화, 상세 페이지 이동 |
| `/app/monitoring` | `monitor_rules`, `geo_alerts`, `workspace_events` | 규칙 생성·조회·편집·삭제, 활성 토글, 즉시 평가, 알림 확인·메모·종료 알림 삭제, 이벤트 이력/검색/페이지 이동 |
| `/app/reports`, `/app/reports/weekly`, `/app/reports/:id` | `report_snapshots`, `report_summaries`, `report_action_items`, `report_preferences` | 주간·월간 생성/목록/상세, 제목·메모, 요약 CRUD, 액션 CRUD·완료·우선순위·기한, JSON/Markdown 다운로드, 자동 생성 설정·초기화 |

대시보드 설정은 워크스페이스와 사용자별로 분리한다. 모든 화면은 선택한 워크스페이스 변경 시 데이터를 다시 조회한다. 실패 응답은 모달 입력을 보존하고, 변경 버전이 다른 저장/삭제는 409로 차단한다. 오래된 데모 리포트는 별도 표시하며 새 대시보드 리포트 목록에는 포함하지 않는다.

## 집계와 근거

- 분석 화면과 같은 계산 함수를 사용한다. 검색은 기간 내 키워드·엔진별 최신 표본, GEO는 기간 내 완료 실행 전체가 기준이다. 반복 질문 실행도 각각 표본으로 포함된다.
- 미래 시각, 현재 문구/언어/국가와 다른 기록, 삭제한 엔티티는 현재 집계에서 제외한다. 미측정은 `null`이며 0으로 바꾸지 않는다. 직전 비교는 같은 길이의 이전 기간이다.
- 검색 점수는 순위·Top 10·AIO 인용 측정 자료가 필요하다. GEO 점수는 인용/멘션 비율과 별도 인용/멘션 순위 점수 4개가 모두 필요하다. 출처 등장 순서를 멘션 순위로 추정하지 않는다. 현재 데모 Provider는 모든 점수 입력을 제공하지 않으므로 점수가 미측정일 수 있다.
- HTML 건강도는 기간 내 완료된 HTML 수집 및 원본 가져오기 진단 중 대상별 최신 점수의 평균이다. 가져온 자료는 `import:<출처>`로 구분하며 리포트 근거에도 출처를 보존한다. 이전 고정 시드 진단은 제외한다. [Raw 데이터 가져오기](raw-data-crud.md) 참고.
- 리포트에는 생성 당시 지표, 표본 ID/텍스트/엔진/시각/Provider/출처 URL을 저장한다. 원본 삭제 후에도 저장한 근거는 유지된다. 원문 답변은 스냅샷에 복제하지 않는다.
- 리포트의 등록 개수는 **생성 당시** 현황이다. 과거 기간 등록 개수로 표시하지 않는다. 측정 기간과 생성 시각, 집계 시점, 진행 중인 기간 여부를 함께 보여 준다.
- 주간은 ISO 주차와 월요일~일요일, 월간은 달력 월, 모두 UTC다. 같은 기간을 명시적으로 다시 생성하면 별도 버전을 보관한다.

## 감시와 예약 실행

`src/lib/backend/observability-worker.ts`를 Node 계측 초기화에서 시작한다. 기본 30초마다 만기 작업을 확인하며 `HALOX_DISABLE_OBSERVABILITY_WORKER=1`로 중지, `HALOX_OBSERVABILITY_INTERVAL_MS`로 확인 간격을 설정한다. 실제 규칙 평가 간격은 5~1,440분이다.

규칙은 검색 Top 10 비율/평균 순위, GEO 인용률/멘션율, HTML 건강도를 지원한다. 기간은 1~90일, 최소 표본 1~10,000개, 비율·건강도 임계값 0~100, 순위 임계값 0~1,000이다. 워크스페이스당 규칙 100개까지 지원한다.

조건 충족 시 열린 알림을 하나만 만든다. 연속 평가로 중복 알림을 만들지 않는다. 정상 측정값이 확인되어야 복구 처리하며, 자료 부족은 열린 알림을 종료하지 않는다. 규칙 정의/활성 상태를 변경하면 이전 조건의 알림을 종료한다. 규칙 삭제 시 관련 알림과 이벤트도 삭제한다. 알림은 모든 멤버가 확인/메모할 수 있고 열린 알림은 삭제할 수 없다.

자동 리포트는 관리자만 설정하며 매주 월요일 또는 매월 1일 지정 UTC 시각에 직전 종료 기간을 저장한다. 재시작 후에는 가장 최근 종료 기간만 처리한다. 중단 중의 모든 과거 기간을 자동으로 채우지 않으며 필요한 기간은 직접 생성한다. 진행 중인 기간의 수동 리포트가 있어도 종료 후 자동 리포트는 별도로 생성한다.

예약 커서·알림 전환·생성 요청 영수증은 SQLite 쓰기 잠금 안에서 함께 저장한다. 여러 실행기/재시작으로 동일 알림·자동 리포트가 중복되지 않는다. 작업별 실패는 해당 항목 변경을 되돌리고 오류와 1시간 후 재시도 시각을 저장한다. 한 트랜잭션에서 최대 20개 작업을 처리한다. 저장소 실패는 트랜잭션 전체를 되돌린다. 워크스페이스 소유자 권한으로 실행한다.

리포트 생성은 비공개 `report_requests`에 요청 키와 입력 서명을 보관한다. 같은 키·같은 입력은 기존 결과를 반환하고, 다른 입력은 409다. 삭제된 리포트의 요청 키는 재사용할 수 없다. 자동 생성 키도 유지되어 삭제한 리포트를 같은 예약으로 되살리지 않는다. 워크스페이스 삭제 시 이 기록도 정리한다. 보관 한도는 워크스페이스당 리포트 200개, 리포트당 액션 100개, 측정 스냅샷 2 MiB다.

## API와 권한

- `GET /api/v1/observability?workspace_id=...&kind=dashboard|monitoring|reports`, 상세는 `report_id=...`.
- `POST /api/v1/functions/dashboard-preferences-save|reset`
- `POST /api/v1/functions/monitor-rule-create|update|delete|check`, `monitor-alert-update|delete`
- `POST /api/v1/functions/report-create|update|delete`, `report-summary-save|delete`, `report-action-create|update|delete`, `report-preferences-save|reset`
- `GET /api/v1/reports/:id/download?format=json|md`: 인증/RLS 확인 후 저장한 근거와 현재 요약·액션을 첨부 파일로 반환. `private, no-store`, `nosniff` 적용. JSON은 전체 근거, Markdown은 요약·지표·메모·액션이다.
- 이전 `report-snapshot`, `generate-weekly-snapshot` 계약도 새 집계로 연결했다. 고정 날짜/가짜 증감 생성은 제거했다.

규칙·자동 리포트 설정은 소유자/관리자만 변경한다. 리포트·요약·액션과 알림 메모는 워크스페이스 멤버가 공동 관리한다. 이 테이블들과 감시 이벤트의 공개 REST 직접 쓰기는 차단했다. 대시보드 설정은 REST 조회도 본인 자료만 보인다. 다른 워크스페이스 조회/쓰기/다운로드를 차단한다.

## 검증

전체 단위 180/180, E2E 60/60, 백엔드 22/22 통과. 타입 검사·프로덕션 빌드 통과. 경로 검사 363개에서 누락/실패/중복/누락 자산 0개이며 기존 원본 404 항목 73개는 기능 완료로 세지 않는다. 최종 HTML Provider 표시 변경은 관측 단위 14/14로 재검증했다.

- 단위: 실제 달력/연도 경계, 미측정/미래값/직전 기간, 삭제 후 재집계, GEO 분모·필수 순위, 최신 HTML 진단, 개인 설정 격리, 재시작/동시 평가, 중복 알림, 자료 부족/복구, 권한/버전 충돌, 스냅샷 보존, 요청 재사용, 삭제 관계, 자동 생성/재생성 방지, 파일 내용, 작업별 롤백.
- E2E: 대시보드 설정/원본 변경, 실제 서버 감시 실행, 알림 확인/삭제, 리포트·요약·액션 CRUD/다운로드, 실제 서버 자동 리포트 실행, 실패 입력 보존/교차 테넌트/REST 차단/모바일 스크롤.
- 모바일에서 기존 공통 `main`의 `min-height:100svh`가 내부 스크롤 영역까지 강제되어 하단을 가리는 문제를 재현했다. 새 화면의 스크롤 영역에 `min-height:0`을 적용하고 실제 휠 입력으로 확인했다.
- Ego Lite 수동 화면 증거: `evidence/2026-10-23-dashboard-crud.png`, `evidence/2026-10-23-monitoring-mobile.png`, `evidence/2026-10-23-monitoring-alert.png`, `evidence/2026-10-23-report-detail.png`, `evidence/2026-10-23-report-mobile.png`. QA 워크스페이스와 브라우저 작업 공간은 정리했다.

## 남은 외부 연동 범위

감시는 저장 자료를 평가하며 외부 문자/이메일 알림, 자동 검색 수집, GSC·GA4 실 OAuth 동기화는 하지 않는다. 외부 연동 S09와 알림 전달 S10은 작업표에 미완료로 유지한다. 요약은 실제 수치를 문장으로 작성하며 외부 AI 요약 호출은 없다. OpenAI 자동 번역은 기존 구현을 유지하며 키는 사용자가 서버 환경변수에 직접 설정한다. 이번 검증에서 실제 OpenAI/SOLAPI 요청은 수행하지 않았다.
