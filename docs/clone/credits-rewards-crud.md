# 크레딧·추천 보상 원장 구현 및 검증

기준일: 2026-10-24. 전체 메뉴 작업표 S14 범위다.

## 모델과 화면

`/app/settings?tab=credits`는 선택한 워크스페이스의 추가 사용량 크레딧과 로그인 계정의 추천 보상을 함께 조회한다. 두 잔액은 목적과 소유 범위가 달라 합산하지 않는다.

- `workspace_credit_balances`: 워크스페이스와 사용량 단위별 현재 잔액과 revision.
- `workspace_credit_ledger`: 적립(`grant`), 사용(`consume`), 회수(`revoke`), 복원(`restore`) 이벤트와 처리 후 잔액.
- 비공개 `referral_rewards`: 추천 가입의 결제 보상 적립·취소·지급 원장.
- `GET /api/v1/credits?workspace_id=<id>`: 네 사용량 단위의 잔액·현재 플랜 사용량·원장과 본인 추천 보상 합계를 반환한다. 응답은 `private, no-store`이며 다른 워크스페이스 접근은 403이다.

워크스페이스 크레딧은 `keyword_create`, `prompt_create`, `content_gen`, `site_audit_scan` 단위로 분리한다. 금액은 1 이상의 안전한 정수이고 이벤트 ID는 전체 원장에서 유일하다. 같은 이벤트와 같은 입력은 기존 행을 반환하며 금액·단위·출처가 달라진 재사용은 거절한다. 잔액을 음수로 만들 수 없다.

적립은 참조 없이 기록한다. 회수는 양수 원장, 복원은 음수 원장을 같은 워크스페이스·단위에서 참조하며 원본 금액을 넘을 수 없다. 사용은 완료된 사용량 예약 ID를 출처로 기록한다. 잘못된 기록을 수정·삭제하는 대신 회수나 복원 원장을 추가한다.

## 사용량 예약과 차감

`reserve_unit_with_bypass`는 플랜 한도를 먼저 사용한다. 요청으로 늘어나는 초과분만 크레딧으로 잡고 `usage_reservations.credit_amount`에 기록한다. 아직 완료되지 않은 예약이 잡은 크레딧도 다른 요청의 가용 잔액에서 제외하므로 동시에 초과 예약할 수 없다.

- 예약 완료(`commit_reservation`): `usage:<reservation-id>:commit` 이벤트로 한 번만 차감한다. 완료 명령을 다시 호출해도 중복 차감하지 않는다.
- 예약 해제(`release_reservation`): 잡아 둔 크레딧을 다시 사용할 수 있게 하며 원장 사용 행을 만들지 않는다.
- 플랜 사용량이 남아 있으면 크레딧은 차감하지 않는다.
- `get_workspace_quota_summary`는 플랜 잔여량, 크레딧 잔액, 대기 중인 크레딧 예약을 반영한 실제 사용 가능량을 반환한다.

`workspace_credit_balances`, `workspace_credit_ledger`, `usage_reservations`는 공개 REST에서 읽기 전용이다. 브라우저에는 크레딧 생성·수정·삭제 명령이 없다. 신뢰된 결제·고객 지원·추천·사용량·이관 서버 어댑터만 기록할 수 있다.

## 결제와 추천 보상

추천 코드로 가입한 계정의 첫 NicePay 결제가 확정되면 `HALOX_REFERRAL_REWARD_KRW`에 설정한 금액을 추천인에게 KRW 보상으로 한 번 적립한다. 기본값은 `0`이므로 운영자가 정책 금액을 명시하기 전에는 보상이 생기지 않는다. 갱신 결제와 플랜 변경 결제는 새 추천 보상을 만들지 않는다.

첫 결제가 전액 취소되거나 NicePay 전액 취소 웹훅이 확인되면 원래 적립 원장을 참조하여 같은 금액을 한 번 회수한다. 이미 일부가 지급된 뒤 취소되면 합계가 음수가 될 수 있으며 이는 정산 채무로 표시한다. 미지급 양수 잔액과 정산 채무 모두 계정 탈퇴를 막는다. 지급 신청과 실제 송금은 제공하지 않으며 `paid` 기록은 신뢰된 정산 어댑터만 만들 수 있다.

```dotenv
HALOX_REFERRAL_REWARD_KRW=0
```

## 검증 범위

- 원장 이벤트 멱등성, 같은 키 내용 변경 거절, 회수·복원 참조와 한도, 음수 잔액 차단.
- 플랜 우선 사용, 초과분만 예약, 동시 예약의 초과 사용 차단, 해제 후 재사용, 완료 재시도의 단일 차감.
- SQLite 재시작 뒤 잔액·원장 보존, 교차 워크스페이스 차단, 공개 REST 쓰기 거절, 응답에서 내부 지문 제외.
- 최초 결제의 단일 추천 적립, 전액 취소의 단일 회수, 중복 웹훅 방어, 양수 보상과 정산 채무의 탈퇴 차단.
- 크레딧·추천 보상 화면, 관련 페이지 이동, 390px 가로 넘침·실제 스크롤 E2E.

전체 단위 테스트 **337/337**, 백엔드 계약 **22/22**(테이블 59개), 전체 E2E **110/110**, 타입 검사와 프로덕션 빌드를 통과했다. 프로덕션 서버에서 경로 **363개**를 다시 확인해 누락·실패·중복·자산 누락이 없었다. 원본 404 73개는 기능 완료 수에 포함하지 않는다.

실제 크레딧 상품 구매 화면, 운영자 수동 조정 화면, 추천 지급 신청과 송금은 이 범위에 포함하지 않았다. 실제 NicePay 결제는 운영 키 설정과 샌드박스·소액 결제 확인이 필요하다.
