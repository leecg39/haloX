# 공용 태그 설정 CRUD

2026-10-23. `/app/settings?tab=tags`를 실제 저장 데이터를 사용하는 화면으로 전환했다. 전체 메뉴 목표는 [작업표](full-crud-tasks.md)를 따르며 아직 진행 중이다.

## 데이터와 화면

`workspace_tag_groups`, `workspace_tags`, `keyword_tag_assignments`, `geo_prompt_tag_assignments`를 키워드·프롬프트 화면과 공유한다. 별도 설정 사본이나 localStorage 레코드는 만들지 않는다. 선택한 워크스페이스의 그룹/태그 생성·조회·수정·삭제, 태그 이름·색상·소속 그룹 변경, 검색·그룹 필터, 양쪽 연결 수와 연결 목록을 제공한다.

연결 관리에서는 키워드와 프롬프트를 각각 선택하고 검색 결과만 일괄 선택/해제할 수 있다. 검색으로 숨겨진 선택도 유지한다. 저장은 이 태그의 연결만 변경하며 다른 태그는 유지한다. 동일한 연결을 다시 저장하면 연결 ID와 수정 시각이 바뀌지 않는다. 각 종류별 2,000개까지 연결하며 초과 시 조용히 잘라 저장하지 않고 오류를 반환한다.

그룹 삭제는 소속 태그를 ‘그룹 없음’으로 이동하며 기존 연결을 유지한다. 태그 삭제는 양쪽 연결을 제거하지만 키워드·프롬프트 본문과 측정 이력은 유지한다. 워크스페이스 삭제는 관련 태그/그룹/연결도 제거한다. 저장 실패·충돌 시 모달과 입력을 유지하며 서버가 저장한 뒤 성공을 표시한다.

## API와 검증

`GET /api/v1/tag-settings?workspace_id=...`는 한 저장 스냅샷에서 그룹·태그·연결 수·연결 ID·선택 가능한 키워드/프롬프트의 최소 필드를 조회한다. `POST /api/v1/tag-settings`는 JSON 명령을 받는다. 모두 인증이 필요하며 응답은 캐시하지 않는다.

| action | 입력 |
|---|---|
| `group-create` | `workspace_id`, `name` |
| `group-update` | `workspace_id`, `id`, `expected_revision`, `name` |
| `group-delete` | `workspace_id`, `id`, `expected_revision`, GET에서 받은 `contents_stamp` |
| `tag-create` | `workspace_id`, `name`, 선택 `color`, `group_id` |
| `tag-update` | `workspace_id`, `id`, `expected_revision`, 수정할 `name`/`color`/`group_id` |
| `tag-delete` | `workspace_id`, `id`, `expected_revision`, GET에서 받은 `links_stamp` |
| `tag-assign` | `workspace_id`, `id`, `expected_revision`, `links_stamp`, 전체 `keyword_ids`와 `prompt_ids` 배열 |

이름은 공백 제거 후 1~60자이며 같은 워크스페이스에서 NFKC·대소문자 정규화로 중복을 거절한다. 색상은 6자리 16진수, 그룹/키워드/프롬프트는 같은 워크스페이스의 실제 항목만 허용한다. ID 배열의 형식·중복·상한·존재를 모두 확인한 후 한 SQLite 쓰기 트랜잭션에서 두 종류의 연결을 변경한다. 오류나 저장 실패 시 부분 변경은 롤백한다.

신규 태그·그룹은 버전 1로 시작하며 이전 저장 자료는 버전 0으로 호환한다. REST와 설정 API의 수정 모두 버전을 증가시킨다. 그룹 삭제로 이동한 태그의 버전·수정 시각도 증가한다. 그룹 삭제는 표시 당시 구성의 해시, 태그 연결 수정/삭제는 표시 당시 연결의 해시까지 비교하며 달라지면 409로 거절한다. 연결을 제거했다 다시 추가하는 변경도 연결 ID가 바뀌므로 감지한다.

설정이나 REST에서 태그 연결을 생성·변경·삭제하면 해당 키워드·프롬프트의 수정 시각을 단조 증가시킨다. 따라서 기존 키워드/프롬프트 편집 창의 오래된 태그 선택이 설정 변경을 덮어쓸 수 없다. 양쪽 저장 함수는 연결 변경 후의 최신 수정 시각을 반환한다.

## 권한

조회에는 기타 메뉴 권한이 필요하고, 생성·수정·그룹 삭제는 쓰기 가능한 멤버에게 허용한다. 분석 권한이 없으면 키워드/프롬프트와 연결 ID를 반환하지 않으며 연결 수와 연결 해시는 `null`이다. 0개로 위장하지 않고 화면에 조회 권한이 없다고 안내한다.

태그 연결 변경과 태그 삭제에는 분석 쓰기 권한도 필요하다. 태그 삭제는 관계를 연쇄 삭제하므로 공통 저장 계층에서도 검사하며 기존 REST로 우회할 수 없다. 뷰어는 허용된 자료를 조회만 한다. 서버는 매 요청 현재 멤버십을 확인한다. 삭제된 멤버·다른 워크스페이스의 접근은 차단한다.
