# 추천 프로그램·피드백 CRUD

2026-10-23. 전체 메뉴 작업표 P17/P18 범위. `/app/referral`, `/app/feedback`, `/app/feedback/:id`를 실제 서버 저장과 연결했다. 전체 메뉴 완료를 뜻하지 않는다.

## 저장 범위와 권한

추천 프로그램과 피드백은 **계정 소유 자료**다. 선택한 워크스페이스를 바꿔도 같은 자료를 표시한다. `WorkspaceProvider`의 인증된 사용자와 오류/재시도를 공유하지만 워크스페이스 ID로 소유자를 정하지 않는다. 피드백 생성 시 선택한 워크스페이스가 있으면 서버에서 멤버십을 확인하고 당시 이름을 참고 정보로 저장한다. 워크스페이스 삭제 뒤에도 계정의 피드백은 유지한다.

SQLite의 비공개 `serverRecords`에 `referral_partners`, `referral_codes`, `referral_invites`, `referral_rewards`, `feedback_threads`, `feedback_replies`, `feedback_events`, `portal_requests`를 보관한다. 공개 REST 테이블 목록에는 추가하지 않는다. 인증된 전용 조회/명령만 사용할 수 있고, 사용자 입력의 owner/admin 값으로 권한을 부여하지 않는다.

추천 연락처·초대·보상은 본인만 조회한다. 피드백은 작성자와 서비스 운영자만 조회한다. 현재 로컬 런타임의 서비스 운영자는 기존 시드 관리자 `ADMIN_USER_ID` (`admin@halox.local`)이며, 워크스페이스 소유자/관리자와 별개다. 일반 워크스페이스 관리자는 다른 사람의 피드백을 읽거나 상태를 변경할 수 없다. 여러 운영자를 지정하는 관리 화면은 이번 범위에 포함하지 않았다.

## 추천 프로그램

| 대상 | 입력·동작 | 정책 |
|---|---|---|
| 파트너 연락처 | 이름/상호 100자, 이메일 254자, 국내 휴대폰 번호, 선택 소개 채널 URL 2,000자 | 최초 등록과 기본 추천 코드 발급을 같은 트랜잭션으로 저장. 본인 조회/수정/삭제 |
| 추천 코드 | 코드 이름 100자, 생성·조회·이름 수정·폐기·가입 링크 복사 | 암호학적 난수 18자리 hex, 전체 고유, 계정당 활성 20개. 폐기 후 재활성화·재사용 불가 |
| 가입 전 초대 | 이메일, 선택 이름 100자, 활성 코드 | 계정당 대기 200개, 같은 이메일 중복/자기 이메일 차단. 이름 수정·삭제 가능. 기록 저장만 하며 이메일 발송은 하지 않음 |
| 확정 가입 | 추천 코드, 가입 시점, 마스킹 이메일 | 실제 휴대폰 인증을 완료한 계정 생성 때만 기록. 사용자 수정·삭제 불가 |
| 보상 원장 | 적립/취소/지급, 통화별 합계 | 신뢰된 서버 정산 어댑터만 기록. 사용자 명령과 공개 REST에서 변경 불가 |

추천 링크는 `/app/signup?ref=<code>`다. 가입 폼에 선택 입력으로 표시하며 지울 수 있다. 가입 서버는 추천 코드 유효성 확인 → 휴대폰 인증 증표 소비 → 계정/워크스페이스 생성 → 추천 가입 기록을 하나의 트랜잭션으로 처리한다. 잘못된 코드로 실패하면 인증 증표도 소비되지 않는다. 폐기된 코드와 자기 추천을 차단하며 한 계정의 가입은 한 추천에만 귀속한다. 기존 대기 초대가 있으면 같은 이메일의 기록을 확정하고, 실제 가입에 사용한 코드로 연결한다.

추천인이 미리 입력한 초대 이메일은 본인 목록에 표시한다. 링크를 통해 바로 가입한 사람의 전체 이메일과 사용자 ID는 노출하지 않는다. 서버는 이메일 일부를 마스킹하고 조회 응답에서 `joined_user_id`를 제거한다. 연락처 삭제 시 대기 초대 삭제·활성 코드 일괄 폐기·확정 초대의 이름/이메일 제거를 함께 처리한다. 이미 확정된 가입과 정산 근거는 보존한다.

`recordReferralReward`는 공개 명령에 등록하지 않은 서버 전용 함수다. 금액은 통화의 최소 단위 양의 정수이며 이벤트 ID 중복 처리와 같은 이벤트의 내용 변경을 차단한다. 취소/지급은 동일 추천·동일 통화의 적립 원장을 참조하고 잔액을 초과할 수 없다. 화면은 통화의 소수 자릿수에 맞춰 금액과 적립/취소/지급/잔액을 표시한다. **실제 결제 콜백·현금 정산·지급 신청은 아직 연결하지 않았으며, 가입만으로 보상을 만들지 않는다.** 후속 S06/S07에서 연동한다.

## 피드백

작성자는 종류(개선 아이디어/버그/질문/기타), 제목 200자, 본문 20,000자로 글을 생성하고 자신의 글을 조회·수정·삭제한다. 본문의 줄바꿈을 보존한다. 계정당 최대 100개이며 목록에 검색·종류/상태 필터·정렬·페이지네이션과 빈 상태를 제공한다. 상세 URL을 다른 계정에서 열어도 내용을 읽을 수 없다.

작성자는 추가 설명을, 서비스 운영자는 답변을 작성한다. 답변은 10,000자, 글당 200개 한도이며 본인 답변만 수정한다. 운영자는 다른 사람이 쓴 본문/답변을 대신 수정할 수 없다. 운영자는 글·답변을 삭제할 수 있고, 작성자는 운영자 답변을 삭제할 수 없다. 글 삭제 시 답변과 처리 이력을 함께 삭제한다.

처리 상태는 접수됨/검토 중/진행 예정/완료/반영 보류다. 서비스 운영자만 상태를 바꾸며 2,000자 이내 사유를 반드시 입력한다. 변경 전후 상태·사유·운영자·시점을 이력으로 저장하고 작성자에게 표시한다. 같은 상태로의 변경을 거절한다. 피드백 등록으로 체험 기간이나 요금제를 자동 변경하지 않는다.

운영자는 ‘내 피드백’과 ‘운영자 전체 접수함’을 전환한다. 두 보기 모두 실제 서버 자료를 읽는다. 일반 사용자가 `view=support`를 요청하면 403이다.

## API와 충돌·재요청

- `GET /api/v1/portal?kind=referral`
- `GET /api/v1/portal?kind=feedback&view=mine|support&thread_id=<선택>`
- `POST /api/v1/functions/referral-partner-save|delete`
- `POST /api/v1/functions/referral-code-create|update|revoke`
- `POST /api/v1/functions/referral-invite-create|update|delete`
- `POST /api/v1/functions/feedback-thread-create|update|delete`
- `POST /api/v1/functions/feedback-reply-create|update|delete`
- `POST /api/v1/functions/feedback-status-update`

성공 조회는 `private, no-store`다. 외부 계정 자료 접근은 403, 낡은 `expected_revision` 또는 동일 요청 키의 내용 변경은 409다. 연락처 최초 등록은 revision 0을 요구한다. 답변 변경은 글의 활동 시각/버전도 갱신한다. 실패한 저장은 폼을 닫거나 성공 알림을 만들지 않고 입력을 유지한다.

코드·초대·글·답변 생성은 계정+요청 키와 입력 해시를 저장한다. 같은 요청은 재시작 후에도 기존 ID를 반환하고 삭제된 항목을 재생성하지 않는다. 요청 기록에는 본문·연락처 원문 대신 해시와 결과 ID만 저장한다. 모든 변경과 요청 기록은 SQLite 트랜잭션으로 반영한다.

## 검증

전체 단위 **208/208**, 전체 E2E **68/68**, 백엔드 **22/22**, 타입 검사·프로덕션 빌드 통과. 마지막 화면 안내/제목 보정 후 추천·가입 E2E **7/7**도 재통과했다. 경로 363개에서 누락/실패/중복/누락 자산 0개다. 기존 원본 404 항목 73개는 기능 완료로 세지 않는다.

- Portal 단위 14개: 계정 격리·직접 REST 차단·버전 충돌·입력 한도·병렬 요청/재시작·삭제 후 재요청, 실제 휴대폰 인증 서비스와 가입 트랜잭션, 잘못된 추천 코드의 증표 보존, 마스킹/자기 추천/중복 귀속 차단, 원장 중복 이벤트·잔액, 연락처 철회, 글/답변/운영자 상태 권한과 연쇄 삭제.
- Portal E2E 4개: 연락처/추천 코드/초대 CRUD·링크 복사·폐기·연락처 삭제, 추천 링크의 선택 입력과 실제 가입 연결, 작성자/운영자 두 세션에서 답변·처리 이력·수정·삭제, 실패 입력 보존/낡은 버전/다른 계정/모바일 실제 스크롤.
- 첫 대상 E2E에서 상태 선택란의 정확 일치 접근성 이름 지정이 맞지 않아 한 건 실패했다. 선택란 레이블 검색만 수정한 뒤 전체 68개를 통과했다. 계정별로 격리한 테스트 사용자를 생성하며 운영 API 제한은 변경하지 않았다.
- Ego Lite에서 연락처 등록·코드 이름 수정·새로고침, 별도 계정 글에 운영자 답변/상태 변경, 상태별 검색 결과와 빈 상태, 추천 링크의 가입 입력을 확인했다. 프로덕션 서버를 재시작한 뒤 연락처·코드·답변·이력이 남아 있음을 확인했다. 계정별 폼의 저장 안내와 추천 페이지 경로 표기도 바로잡았다.
- 1428px 데스크톱과 390px 모바일에서 배치와 가로 넘침을 확인했다. 모바일 피드백 휠 입력 후 실제 스크롤 위치가 356px로 이동했다. 테스트는 별도 SQLite 파일에서 수행하며 개발 DB는 변경하지 않는다. 실제 SMS/OpenAI/이메일/결제 요청은 수행하지 않았다.
- 화면 검증 후 TaskSpace 47과 3110 포트의 임시 서버를 종료하고 검증용 SQLite 디렉터리를 삭제했다. 개발 서버와 개발 DB는 유지했다.

OpenAI 자동 번역은 이전 단계에서 구현했다. 사용자가 서버의 `OPENAI_API_KEY`를 직접 설정한다. 관련 설정은 [자동 번역 문서](automatic-translation.md)에 있다. 실제 SOLAPI 발송 역시 사용자 서버 환경변수 설정 후 별도 수신 확인이 필요하다.
