# 키워드 메뉴 풀스택 CRUD

2026-10-23. `/app/keywords`와 동적 `/app/keywords/:id`는 수집 HTML의 본문을 실제 React 화면으로 교체했다. 사이드바와 헤더는 기존 외형을 유지한다. 키워드 페이지에는 로컬 레코드 삽입이나 먼저 성공을 알리는 비동기 동기화를 적용하지 않는다.

## 화면과 저장 모델

| 화면 | 작업 / 모델 |
|---|---|
| 리스트·상세 | `keywords`: 생성, 조회, 편집, 일시정지/재개, 개별/선택 삭제. 검색·세트/상태/의도 필터·정렬·12개 단위 페이지네이션·CSV 다운로드 |
| 상세 수집 이력 | `serp_snapshots`: 서버 수집 생성·조회. 원본을 직접 편집하지 않는다. 키워드 삭제 시 함께 삭제 |
| 세트 | `keyword_sets`: 이름·설명·자사 도메인·언어/국가·기본 여부 CRUD. 세트 삭제 시 키워드와 아이디어는 미분류로 보존 |
| 태그 | `workspace_tags`, `workspace_tag_groups`: 이름·색상·그룹 CRUD. 키워드 편집에서 `keyword_tag_assignments`를 원자적으로 변경. 태그 삭제 시 연결 삭제, 그룹 삭제 시 태그 보존 |
| 네트워크 | `keyword_prompt_links`: 실제 등록된 키워드와 프롬프트의 연결 생성·목록·수정·삭제 |
| 아이디어 | `keyword_ideas`: 키워드·메모·세트·언어/국가 CRUD. 채택 시 키워드/수집 이력 생성과 아이디어 제거를 한 트랜잭션으로 처리 |

현재 SERP Provider는 결정적 데모 구현이다. 화면에 모의 데이터라고 표시하며 실제 외부 검색을 수행했다고 주장하지 않는다. 자사 순위는 현재 세트/워크스페이스 도메인과 수집 결과 URL의 호스트를 비교한다. 수집 결과에 자사 도메인이 없으면 순위를 만들지 않는다. 키워드 텍스트·국가·언어 변경 시 기존 검색량/의도를 비우고 과거 이력과 현재 지표를 분리한다.

## API·권한

- `GET /api/v1/keywords?workspace_id=<id>`: 인증 및 멤버십 확인 후 9개 관련 테이블을 **동일 저장소 스냅샷**에서 반환. 기존 9회 조회를 한 번으로 줄였다. 캐시는 `private, no-store`.
- `POST /api/v1/functions/keywords-collect`: 최대 20개 입력 검증 → 선택한 공간의 세트 확인 → 한도 예약 → 키워드·수집 이력 → 커밋. 세트 생략 시 해당 공간에서 찾거나 생성한다. 실패 시 SQLite 트랜잭션 전체 롤백.
- `keywords-save`: 수정 시각 비교 및 필드/태그 검증 후 키워드와 태그 연결을 함께 저장. 오래된 폼은 덮어쓰지 않는다.
- `keywords-refresh`: 기존 키워드에 수집 이력 추가. 키워드 중복 생성이나 생성 한도 재차감 없음. 일시정지 상태 유지.
- `keywords-adopt-idea`: 기존 아이디어를 단회 채택. 재요청 시 이미 채택/삭제되었다는 오류.
- 세트·태그·그룹·관계·아이디어는 기존 REST CRUD를 사용한다. 공개 REST는 수정 가능한 필드만 받으며 수집 지표·수집 이력을 직접 변경할 수 없다. 키워드 생성은 한도 검증을 거치는 수집 함수로만 가능하다.
- 참조 대상은 **같은 워크스페이스**에 있어야 한다. 사용자가 두 공간 모두의 소유자여도 교차 참조는 거부한다.

`WorkspaceProvider`는 서버에서 확인한 접근 가능한 ID만 사용한다. 전환 시 키워드 화면의 조회·필터·폼 상태를 새 공간으로 초기화하고 이전 요청 결과를 반영하지 않는다. localStorage는 선택한 공간만 기억하며 레코드 저장소로 쓰지 않는다.

## 검증과 화면 증거

최종 실행: `npm run build`, `npm run typecheck` 통과. 단위 **77/77**, E2E **25/25**, 백엔드 계약 **22/22** 통과. E2E는 개발 데이터와 분리된 SQLite 파일에서 실행했다.

- `src/lib/backend/keywords.test.ts`: 새 공간 기본 세트, 중복/잘못된 입력, 교차 공간 참조, 태그와 본문 원자 저장, 오래된 폼, Provider 실패 롤백, 삭제 관계 정리, 아이디어 단회 채택.
- `e2e/keywords.spec.ts`: 실제 HTTP 저장 후 새로고침·동적 상세·편집·재수집·삭제, 저장 실패 시 입력 보존, 선택한 공간의 읽기/쓰기, 아이디어 채택·프롬프트 연결, 모바일·페이지네이션·필터·선택 삭제·Escape.
- 기존 J1은 실제 화면/서버 응답으로 성공을 확인하고 생성 한도 차감을 검증한다. 워크스페이스 삭제 테스트도 수집 API로 관계를 만든다.
- Ego Lite에서 관리자 로그인 후 세트/키워드 생성 → 상세 조회 → 삭제를 확인했다. 검증용 항목만 삭제했다.
