# 사이트 진단 정책 파일과 사이트맵 통계 보완

2026-10-24. S02 `/app/settings?tab=workspace`의 사용자 지정 robots.txt·sitemap.xml·llms.txt 주소와 기존 진단의 사이트맵 통계 보완을 구현했다. 전체 메뉴 작업은 [작업표](full-crud-tasks.md)를 따른다. 원본의 계정 탈퇴·30일 복원은 별도 S13으로 남아 있다.

## 설정과 진단

워크스페이스 소유자·관리자 중 전략 메뉴 쓰기 권한이 있는 사용자가 세 주소를 조회·수정·초기화한다. 공개 HTTP/S 표준 포트 URL만 허용하며 인증 정보·내부망·fragment를 거절한다. 설정 수정은 `expected_revision`을 확인한다. 503/409/검증 실패 때 편집 내용을 유지한다. 일반 REST에서 정책 필드를 직접 변경할 수 없다.

빈 값은 각 진단 대상 origin의 `/robots.txt`, `/sitemap.xml`, `/llms.txt`를 사용한다. 사용자 지정 사이트맵이 없으면 robots의 `Sitemap` 선언을 우선하며 모두 부적합하면 기본 경로를 탐색한다. 새 진단은 `policy_snapshot`에 당시 설정을 저장하고 같은 범위 재실행도 그 설정을 재사용한다. URL 스냅샷은 파일 내용의 과거 버전을 복원하지 않는다.

robots 규칙과 수집 간격을 확인한 뒤 사이트맵 인덱스를 순회하고 범위·robots에서 허용한 URL을 HTML 수집 후보에 추가한다. 추가 후보는 최대 100개이며 실제 수집은 진단의 페이지·깊이 제한을 따른다. llms.txt는 제목·제목 수·링크 수만 기록하고 내용으로 모델을 호출하지 않는다. 문서의 요청/최종 URL·상태·HTTP·타입·바이트·SHA-256·확인 시각을 `policy_report`에 보존한다. HTML 점수와 사이트맵 URL 수는 별도 지표다.

## 기존 진단 보완과 이력 CRUD

`POST /api/v1/workspace-management`의 `policy-update`, `policy-reset`, `sitemap-backfill-start/cancel/update/delete`를 사용한다. 조회 응답에는 현재 워크스페이스의 `policy_jobs`와 `policy_editable`을 포함한다. 진행 중에는 화면을 3초마다 갱신한다.

| 저장 위치 | 내용 |
|---|---|
| `workspaces` | 세 정책 파일 URL, 기존 revision |
| `site_policy_jobs` | 실행 당시 URL 설정, 상태, 대상/처리/미확인 수, 진단별 결과, 이름·메모, revision |
| 비공개 `site_policy_work` | 대상·진행 커서·파일 탐색 상태·작업 점유와 재시도 횟수 |
| 비공개 `site_policy_requests` | 사용자·워크스페이스·요청 키·실행 ID |
| `site_audit_scans.sitemap_backfill_report` | 최근 보완 시점의 통계·파일 근거·작업 ID |

한 번에 종료된 진단 최대 100개를 처리하며 워크스페이스당 진행 작업 하나, 이력 최대 100개다. 초과하면 명시적으로 거절한다. 보완은 **현재 파일**을 읽고 새 결과를 별도로 저장한다. 기존 HTML·점수·당시 정책 근거를 덮어쓰지 않는다. 이력은 이름·메모 수정과 삭제가 가능하며 삭제해도 진단의 보완 결과는 남는다. 후속 보완이 성공하면 최근 보완 결과를 갱신한다.

동일 요청 키는 재시작 후에도 기존 작업만 반환하며 이력을 삭제한 뒤 재전송해도 새 작업을 만들지 않는다. 취소 후 늦게 도착한 응답은 반영하지 않는다. 이미 처리한 진단 결과는 유지한다. 워크스페이스 삭제는 작업·요청 키도 정리한다. 종료된 진단을 보완 중 삭제했다면 그 항목은 미반영으로 기록한다.

## 실행과 제한

기존 사이트 진단 실행기에 연결했다. 한 주기에 문서 하나를 처리하고 HTTP 요청은 SQLite 쓰기 잠금 밖에서 실행한다. 원본 HTML 수집과 origin별 작업 점유·수집 간격을 공유한다. 작업 점유는 45초, 반복 중단은 최대 3회이며 저장된 상태에서 재개한다. `HALOX_DISABLE_AUDIT_WORKER=1`이면 진단과 보완 모두 자동 실행하지 않는다.

- 공개 DNS 주소를 검사한 뒤 해당 주소로 연결하고 리디렉션도 검증한다. 정책 파일은 설정한 source origin 안에서만 리디렉션하며 사이트맵 인덱스의 하위 문서도 같은 origin으로 제한한다. 명시한 CDN 정책 파일은 허용한다.
- 정책 문서 최대 10개, 사이트맵 인덱스 깊이 3, URL 10,000개, XML 2MiB, robots/llms 512KiB, UTF-8 텍스트만 지원한다. 압축 응답/파일은 지원하지 않는다. 한도 도달은 부분 집계로 표시한다.
- `saxes@6.0.0`으로 XML 문법·namespace·loc 개수/길이·중첩을 검사하며 DTD/외부 엔티티를 거절한다. XML Schema 전체 검증이나 검색엔진 색인 확인은 아니다. 근거: [Sitemaps 프로토콜](https://www.sitemaps.org/protocol.html), [saxes 공식 저장소](https://github.com/lddubeau/saxes).
- robots의 4xx(429 제외)는 파일 없음/접근 불가로 기록하고 진행한다. 네트워크 오류·5xx·429는 robots 미확인으로 중단한다. 404로 파일이 없는 것과 형식 오류·점검 실패를 구분한다. 근거: [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html).

## 검증

최종 전체 단위 **274/274**, 전체 E2E **91/91**, 백엔드 계약 **22/22**, 타입 검사·프로덕션 빌드 통과. 363개 경로에서 누락·실패·중복·자산 누락 0개이며 원본 404 73개는 기능 완료 수에서 제외한다.

새 단위 8개는 XML/URL·인덱스/중복/범위·한도/오류·잘못된 선언의 기본 경로 탐색·스냅샷/재진단·원본 보존/이력 CRUD·권한/REST·취소/점유/재시작·내부망/리디렉션 거절을 검증한다. 새 E2E 3개는 실제 HTTP 저장/실패/충돌/초기화, 새 진단·기존 진단 보완·이력 CRUD/취소, 워크스페이스/뷰어/메뉴 격리·390px 스크롤을 확인한다.

첫 전체 E2E는 90/91이었다. 기존 취소 테스트가 robots 뒤 첫 HTML이 수집된다고 가정했으나 사이트맵·llms 단계가 추가되어 아직 HTML 수집 전이었다. fixture의 없는 파일을 404로 명시하고 정책 3개 뒤 HTML 1개가 수집된 시점에서 취소하도록 수정했다. 실제 취소 동작과 기대하는 보존 조건은 유지했다.

Ego Lite의 별도 서버·임시 SQLite에서 주소 저장/새로고침, 보완 시작, 정책 파일 처리 도중 서버 종료/같은 DB 재시작, 별도 실행기 프로세스에서 남은 파일 처리, 완료 상태와 메모 저장을 확인했다. HTML 점수 73과 원래 정책 근거가 유지됐다. 공개 사이트 응답은 통제한 fixture이며 이번 검증이 실제 고객 사이트의 파일 내용/접근 성공을 의미하지 않는다. OpenAI·SOLAPI·이메일·결제 요청은 보내지 않았다.
