# 콘텐츠 최적화 CRUD와 본문 적용

2026-10-23. `/app/optimize` 및 `/app/optimize/:id`를 실제 워크스페이스의 진단·제안·콘텐츠 버전에 연결했다. 이전의 고정 점수/제안 반복 삽입 함수를 교체했다.

## 화면과 상태

1. **본문 진단**: 제작소의 현재 버전 선택, 본문 직접 입력, 공개 URL 가져오기 중 하나로 시작한다. 직접 입력·URL은 제작소에도 원본 v1으로 저장한다. 글자 수·구성 수·검색 설명/요약 제목 여부는 저장한 원문에서 계산한다.
2. **검색 참고 수집**: 현재 Provider의 데모 검색 참고를 저장하고 화면에 데모임을 표시한다. 실시간 SERP로 주장하지 않는다.
3. **제안 검토**: 원문에서 추출한 요약/검색 설명 제안을 만들고 이름·내용·이유·적용 방법을 편집할 수 있다. 사용자 제안 추가/삭제와 적용 대상 포함·제외도 저장된다.
4. **본문 적용**: 선택한 제안을 목록 순서대로 실제 새 버전에 반영한다. 원문은 유지한다. 적용 후 원본 복원은 또 다른 버전을 만든다.

목록은 검색·상태 필터·10개 단위 페이지 이동을 제공한다. 상세에서 진단 이름/메모를 변경하고 원문·적용/복원 결과를 비교한다. 제작소에서 최적화를 시작하거나, 진단 상세에서 제작소로 이동할 수 있다. 실패 시 입력을 유지하며 선택 상태 저장 실패는 체크박스를 원래 상태로 되돌린다. 진단 이후 콘텐츠 변경 시 적용을 막고 현재 버전의 새 진단을 안내한다.

## 모델 및 API

| 모델 | 필드 / 정책 |
|---|---|
| `content_review_runs` | 워크스페이스, 이름/메모, URL/주제, 원문 유형·가져온 시각, 콘텐츠·원본 버전·기준 revision, 원문 스냅샷, 실제 구조 진단, 검색 참고, 단계, 자체 revision, 적용/복원 버전 연결 |
| `content_change_items` | 진단 연결, 순서, 이름/이유, 대상 필드, 앞/뒤 추가 또는 일치 문구 교체, 변경 전/후 내용, 검토/제외/적용 상태, 적용 버전 연결 |
| `content_drafts` / `content_compositions` | 제작소와 같은 저장 함수를 사용한다. 원문·적용·복원마다 독립 버전과 구성을 보존한다. |

`GET /api/v1/optimization?workspace_id=...`가 일관된 스냅샷을 반환한다. 인증·워크스페이스 권한을 검사하고 캐시하지 않는다. 모든 쓰기는 `POST /api/v1/functions/{명령}`이며 공개 REST에서 진단·제안을 직접 변경할 수 없다.

| 명령 | 입력 / 동작 |
|---|---|
| `optimize-audit-content` | `workspace_id`, `job_id` + `expected_content_revision`, 또는 `source_mode=text/url`과 본문/URL·주제. 진단과 원문 스냅샷을 만들고 생성 사용량 1회를 처리한다. |
| `optimize-serp-fetch` | `review_run_id`, `expected_revision`. 진단 완료 상태에서 검색 참고를 저장한다. |
| `optimize-strategy-synthesis` | 같은 입력. 검색 참고 수집 이후 제안 두 개를 한 번 생성한다. |
| `optimize-review-update` | 같은 입력 + `title`, `notes`. 이름·메모를 수정한다. |
| `optimize-change-create/update/delete` | 같은 입력 + `change_id`(수정/삭제), 제안 필드. 제안 검토 단계에서만 허용한다. |
| `optimize-rewrite-content` | 같은 입력 + `change_ids`. 이 진단에서 검토 중인 선택 항목만 새 본문 버전에 적용한다. |
| `optimize-restore-original` | 같은 입력 + `expected_content_revision`. 적용된 버전이 아직 현재 버전일 때 원본을 새 버전으로 복원한다. |
| `optimize-review-delete` | 같은 입력. 진단·제안을 삭제하고 제작소의 원문/결과 버전은 유지한다. |

제안 대상은 `content_md`, `title`, `meta_title`, `meta_description`이다. 본문은 prepend/append/replace, 제목·메타는 replace를 지원한다. 본문 교체 원문은 정확히 한 번 있어야 한다. 메타 교체는 현재 값과 일치해야 한다. 겹치는 제안, 빈 제목/본문, 길이 초과는 전체 적용을 롤백한다. 제안은 최대 50개, 제목 200자, 이유 2,000자이며 결과 본문/메타는 제작소 제한을 따른다.

원문 revision 또는 진단 revision 충돌은 HTTP 409다. 적용을 반복하거나 단계 순서를 건너뛸 수 없다. 진단이 참조하는 원본·적용·복원 버전은 제작소에서 개별 삭제할 수 없다. 콘텐츠 전체 삭제는 진단·제안도 정리한다. 이전 구현의 본문 없는 데모 이력은 조회/이름 수정/삭제만 허용하고 새 진단을 안내한다.

## 공개 URL 가져오기

- 실제 Node HTTP(S) 요청으로 서버에 공개된 HTML 또는 텍스트를 가져온다. 인증 쿠키·외부 자격증명을 보내거나 JavaScript를 실행하지 않는다.
- 표준 HTTP/HTTPS 포트만 허용한다. URL 자격증명, loopback/사설/링크 로컬/멀티캐스트/예약 주소 등을 거절한다. DNS의 모든 응답을 검사한 다음 검증한 IP로 연결을 고정한다. HTTP 클라이언트가 다시 DNS를 조회하지 않는다.
- 리디렉션은 최대 3회, 매번 URL/DNS를 다시 검사한다. 전체 DNS/연결/다운로드 제한 8초, 헤더 16KB, 응답 본문 2MB, 최종 텍스트 100,000자. 압축 응답과 UTF-8이 아닌 본문은 거절한다.
- HTML의 제목·검색 설명·본문을 읽고 탐색/스크립트/폼 등을 제외한다. article→main→body 순서로 본문을 선택한다. 원문 URL과 가져온 시각을 보관한다. 로그인/JS 전용 페이지는 직접 본문 입력을 사용한다.
- 현재 SQLite 전체 상태 트랜잭션 안에서 수행하므로 URL 가져오는 동안 다른 쓰기가 대기할 수 있다. 장기 작업 큐와 취소는 공통 F10 후속 범위다.
