# 브랜드 추적 설정 CRUD

2026-10-24. `/app/settings?tab=brand-tracking`를 실제 저장 자료를 사용하는 화면으로 전환했다. 전체 메뉴 목표는 [작업표](full-crud-tasks.md)를 따르며 아직 진행 중이다.

## 화면과 데이터

자사·경쟁사 브랜드 카드의 대표 이름, 멘션, 도메인, 연결 키워드 세트와 제품을 생성·조회·수정·삭제한다. 같은 종류의 브랜드는 명시적인 병합 버튼으로 합칠 수 있다. 병합은 원래 이름을 멘션으로 남기고 멘션·도메인·제품·세트 연결을 대상 브랜드로 옮긴다. 같은 이름의 제품이 겹치면 먼저 이름을 수정하도록 안내한다.

브랜드 카드의 상품과 자사 제품 라인업은 같은 `brand_products` 레코드다. 제품 이름·별도 멘션·카테고리·URL·소개를 저장하며 경쟁사 제품도 해당 카드에서 관리한다. 브랜드 삭제는 소속 제품과 세트 연결을 정리하지만 키워드·프롬프트·수집 원문은 삭제하지 않는다. 도메인 별칭은 이전 도메인에서 대표 도메인으로의 매핑이며 생성·수정·삭제할 수 있다.

브랜드와 제품 노출 수는 최근 28일 완료된 GEO 응답에서 실제로 텍스트가 매칭된 응답 개수다. 출처에 도메인만 등장한 것을 멘션으로 세지 않는다. 최근 관측 도메인은 저장된 SERP·GEO 출처에서 추출하며 사용자가 관련성을 확인한 후 브랜드에 등록한다. 기존 도메인으로 브랜드 이름이나 제품을 AI 추정해 생성하지 않는다.

재계산 이력에는 실행 시각·이유·설정 버전·당시 설정·처리한 SEO/GEO 건수를 저장한다. 메모 수정과 이력 삭제를 제공하며 이력을 삭제해도 현재 설정과 분석 결과는 유지한다. 저장 실패와 충돌 시 입력을 보존하고 서버 저장 완료 후 성공을 표시한다. 선택한 워크스페이스에 따라 조회와 쓰기가 함께 바뀐다.

## 분류 기준과 원본 보존

- 처음 설정을 저장하거나 수동 재계산을 실행하기 전에는 기존 세트·워크스페이스 도메인 기준을 유지한다. 예전 `brands`의 자사/경쟁사 도메인 배열은 카드로 한 번 변환하되 분류를 자동 활성화하지 않는다. 삭제한 경쟁사 카드는 재시작 시 다시 생성하지 않는다.
- 루트 정책은 등록 도메인을 기준으로 서브도메인을 묶는다. `co.kr` 등 공용 접미사와 `github.io` 같은 사설 호스팅 접미사를 구분하도록 `tldts@7.4.19`의 `allowPrivateDomains`를 사용한다. 전체 정책은 호스트의 정확한 일치만 허용한다. 근거: [tldts 공식 문서](https://github.com/remusao/tldts).
- URL 형식으로 입력한 도메인은 호스트로 정규화한다. 경로·쿼리·포트·인증 정보·IP·공용 접미사만 있는 값·로컬 호스트는 거절한다. IDNA, 소문자, 마지막 점 정규화를 적용한다. 별칭은 현재 도메인 정책에 따라 해석하며 출발 중복·자기 참조·순환·다른 브랜드와의 도메인 충돌을 거절한다.
- 대표 이름도 멘션이다. NFKC·대소문자·공백을 정규화하고 ASCII 이름은 단어 경계를 확인해 `Apple`이 `pineapple`에 잘못 매칭되지 않게 한다. 한글 등 비ASCII 이름은 조사를 허용하는 부분 문자열 매칭이다. 따라서 자연어 중의 동명이인이나 짧은 이름은 사용자가 적절한 멘션을 선택해야 한다.
- 키워드 세트를 특정 자사 브랜드에 연결하면 해당 세트의 SEO는 그 브랜드를 기준으로 분류한다. 미연결 세트와 GEO는 모든 자사 브랜드를 사용한다. SEO 분석 화면에서 직접 지정한 비교 도메인은 우선한다. 세트 이동·삭제 후에도 기존 결과의 분류를 갱신한다.
- 설정 저장과 수동 재계산은 모든 저장 SEO/GEO 결과를 한 트랜잭션에서 재분류한다. 이후 키워드 수집·GEO 실행·Raw 가져오기에도 같은 기준을 적용한다. 원본 SERP 결과, 응답 텍스트, 수집 당시 도메인, 원본 응답과 가져온 파일 바이트는 유지한다. 최초 제공자 분석과 인용/멘션 판정은 `provider_analysis_json`·`provider_classification`에 보존한다. 이미 생성한 리포트·콘텐츠 스냅샷은 변경하지 않는다.
- 도메인이나 텍스트 기준이 없으면 관련 지표는 `null`로 두고 미측정으로 표시한다. 변경된 브랜드의 정확한 순위 점수를 복원할 근거가 없는 GEO 인용/멘션 순위 점수도 `null`로 두며 기존 제공자 값은 보존한다. 유효한 자사 기준과 출처가 있고 인용이 없을 때의 0과 구분한다.

## API·권한·충돌

`GET /api/v1/brand-settings?workspace_id=...`는 설정·브랜드·제품·별칭·최소 세트 정보·최근 집계·이력을 같은 저장 스냅샷에서 조회한다. 인증과 기타/분석 메뉴 읽기 권한이 필요하다. 응답은 캐시하지 않는다.

`POST /api/v1/brand-settings`는 `workspace_id`, `action`, `expected_revision`과 작업별 필드를 받는다.

| 작업 | 추가 필드 |
|---|---|
| `policy-update` | `mode`: `root` 또는 `full` |
| `brand-create/update` | 수정 시 `id`, `brand_name`, `role`, `mentions`, `domains`, `keyword_set_ids` |
| `brand-delete` | `id` |
| `brand-merge` | 원래 브랜드 `id`, 대상 `target_id` |
| `product-create/update` | 수정 시 `id`, `brand_id`, `name`, `mentions`, `category`, `url`, `description` |
| `product-delete` | `id` |
| `alias-create/update` | 수정 시 `id`, `source`, `target` |
| `alias-delete` | `id` |
| `recalculate` | 요청마다 고유한 `idempotency_key` |
| `job-update/delete` | `id`, 해당 이력의 `expected_revision`, 수정 시 `notes` |

설정 변경에는 전역 설정 버전을 비교하며 오래된 편집은 409로 거절한다. 재계산 메모/삭제는 이력 자체 버전을 비교한다. 수동 실행 요청 키는 비공개 저장소에서 보존하므로 재시도해도 중복 실행하지 않는다. 이력을 삭제한 뒤 같은 키를 재사용해도 다시 실행하지 않는다. 워크스페이스 삭제 시 해당 비공개 요청 자료도 정리한다.

변경은 기타/분석 쓰기 권한이 있는 소유자·관리자만 가능하다. 일반 멤버와 뷰어는 조회만 허용한다. 매 요청 현재 멤버십을 확인하며 메뉴 권한 회수·멤버 삭제·다른 워크스페이스 참조를 차단한다. 관련 5개 테이블의 직접 REST 변경도 차단한다.

전체 후보 설정을 검증한 후 저장한다. 이름·멘션 중복, 도메인 충돌, 제품의 브랜드 참조, 세트의 워크스페이스와 단일 자사 연결, 문자열 길이를 검사한다. 워크스페이스당 브랜드 100개·제품 500개·별칭 200개, 브랜드별 도메인/멘션 50개·세트 100개 한도를 둔다. SQLite 쓰기 잠금에서 설정·파생 결과·이력을 원자적으로 저장하므로 실패 시 모두 롤백한다.

## 검증과 범위

- 새 단위 10개: 공용/사설 접미사와 IDNA, 단어 경계, 별칭 순환/충돌, 구형 카드 변환, SEO/GEO 재분류와 제공자 원본 보존, 세트 연결 변경, 제품/병합/삭제, 신규 수집과 Raw 가져오기, 역할·메뉴 범위·테넌트 격리, SQLite 동시 수정·롤백·재개방·멱등성과 삭제.
- 새 E2E 3개: 카드·제품·별칭·매칭 정책과 분석 연동, 503 입력 보존, 별도 로그인에서 지속성, 병합과 전체 CRUD, 이력 CRUD, 409 입력 보존, REST 우회 거절, 뷰어 제품 상세 닫기, 권한 회수·워크스페이스 전환·390px 실제 스크롤.
- 전체 단위 **255/255**, 최종 전체 E2E **85/85 (2.6분)**, 백엔드 계약 **22/22**, 타입 검사·프로덕션 빌드 통과. 이번 전체 E2E 두 번 모두 통과했으며 마지막 실행은 읽기 전용 제품 상세 닫기 보완까지 포함한다.
- 경로 **363개**에서 누락·실패·중복·자산 누락 0개, 원본 404 73개. 최초 경로 검사는 실행 중인 서버가 없는 기본 포트 3001을 사용해 실패했고, 검증 서버 3110을 명시한 최종 검사는 통과했다.
- Ego Lite TaskSpace 52, 별도 3110 서버와 임시 SQLite에서 자사·멘션·세트 연결, 제품·별칭 생성과 수동 재계산을 실제 화면으로 실행했다. 브랜드/제품 멘션 1건과 SEO 1건·GEO 1건 처리 이력을 확인했다. 서버 종료/재시작 후 카드·제품·별칭·세트 연결·수동 이력이 그대로 유지됐다. 1428×747 화면의 문서 너비는 1428px, 390×600 화면의 문서 너비는 390px이며 실제 본문 스크롤 1068px를 확인했다. 제품 상세 열기/닫기도 확인했다.
