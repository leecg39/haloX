# 콘텐츠 제작소 CRUD와 버전 관리

2026-10-23. `/app/factory` 및 `/app/factory/:id`를 선택한 워크스페이스의 SQLite 저장 데이터에 연결했다. 수집 HTML은 공통 내비게이션으로 사용하고 본문 영역은 실제 목록·편집기로 교체했다.

## 화면

- 직접 작성 또는 페르소나·지식 자료를 선택한 데모 초안 생성. 키워드·프롬프트 연결과 원문 URL 기록.
- 제목/주제 검색, 상태 필터, 수정일·생성일·제목 정렬, 10개 단위 페이지 이동.
- 제목·Markdown 본문·검색 제목/설명 편집. 저장할 때 새 버전을 만들며 원본 본문 공백까지 유지한다.
- 작업 주제·메모·상태(초안/검토 중/사용 준비)·원문 URL·키워드/프롬프트 연결 수정.
- 저장된 버전 미리보기, 현재 버전 선택, 이전 버전을 새 번호로 복원, 개별 버전 삭제, 콘텐츠 전체 삭제.
- 본문의 `##` 제목으로 버전별 구성을 저장한다. 본문에서 섹션을 추가·수정·삭제하면 새 버전의 구성도 바뀐다. 코드 블록 안의 제목 표기는 구성으로 취급하지 않는다.
- 실패 시 입력 유지, 처리 중 중복 제출 제한, 저장 충돌 안내, 명시적인 최신 버전 불러오기. 워크스페이스를 바꾸면 이전 공간의 편집기를 제거한다.
- 페르소나·자료 상세의 생성 이력에서 제작소 편집기로 이동할 수 있다.

## 모델과 API

| 모델 | 주요 필드 / 정책 |
|---|---|
| `content_jobs` | 제목, 주제, 메모, 상태, 원문 URL, 키워드/프롬프트/페르소나/자료 연결. `current_draft_id`, `latest_version`, `revision`은 서버가 관리한다. |
| `content_drafts` | 콘텐츠별 버전 번호, 제목/본문/메타, 선택 상태, 작성 경로, 복원 원본 번호, 생성 당시 참조 스냅샷. 본문은 제자리 수정하지 않는다. |
| `content_compositions` | 버전의 H2 제목·본문·순서. 본문에서 파생하므로 독립 REST 쓰기를 허용하지 않는다. |

`GET /api/v1/content?workspace_id=...`는 콘텐츠/버전/구성 및 선택 가능한 참조 항목을 한 스냅샷으로 조회한다. 로그인과 워크스페이스 멤버십을 검사하고 응답 캐시를 금지한다.

쓰기: `POST /api/v1/functions/{명령}`. 모든 새 CRUD 명령에 `workspace_id`가 필요하다.

| 명령 | 입력과 동작 |
|---|---|
| `content-create` | `title`, `target_keyword`, `content_md` 및 선택 메타/연결. 직접 작성한 v1을 만들며 생성 사용량을 차감하지 않는다. |
| `content-draft` | 주제·페르소나/자료로 데모 초안 생성. `job_id`를 지정하면 기존 작업에 새 버전 생성. 생성 사용량 1회와 버전 저장을 한 트랜잭션으로 처리한다. |
| `content-save` | `job_id`, `expected_revision`, 제목/본문/검색 메타. 새 버전으로 저장하고 선택한다. |
| `content-update` | `job_id`, `expected_revision`, 주제/메모/상태/원문 URL/키워드/프롬프트 연결만 수정한다. |
| `content-select` | `job_id`, `expected_revision`, `draft_id`. 기존 버전을 선택한다. |
| `content-restore` | 같은 입력. 지정한 내용을 새 버전으로 복사하고 선택한다. |
| `content-delete-version` | 같은 입력. 현재 버전이나 최적화 이력에서 참조하는 버전의 삭제는 거절한다. |
| `content-delete` | `job_id`, `expected_revision`. 작업·버전·구성·연결된 최적화/제안을 삭제한다. 기존 내보내기 이력은 작업 연결을 해제하고 유지한다. |

기존 작업 변경에는 서버에서 읽은 `expected_revision`이 필요하다. 충돌은 HTTP 409 `CONTENT_CONFLICT`이며 트랜잭션 전체를 롤백한다. A→B→A 버전 선택 이후에도 예전 revision으로 덮어쓸 수 없다. 삭제한 최고 버전 번호를 재사용하지 않는다. 이전 구현에서 생성한 작업은 revision 0과 `is_selected`를 읽어 첫 변경 시 새 포인터·버전 관리로 이어진다. 구성은 이 구현에서 저장한 버전부터 제공한다.

공개 REST를 통한 작업·버전·구성의 모든 쓰기를 차단했다. 저장 명령에 위조한 생성 참조/점수를 보내도 반영하지 않는다. 수정한 본문의 이전 SEO/AIO 점수는 복사하지 않는다. 생성 참조는 버전별로 보존하며, 참조 없는 직접 작성 버전으로 돌아오면 이후 데모 생성 자료가 섞이지 않는다. 키워드·프롬프트·페르소나·자료를 삭제하면 현재 연결을 해제하되 저장된 스냅샷은 유지한다.

입력 제한: 제목/주제/검색 제목 200자, 본문 100,000자, 검색 설명 1,000자, 메모 5,000자. 원문 URL은 http/https 주소만 허용하며 **주소를 자동 수집하지 않는다**.

## 검증 및 남은 범위

최종 검사: 단위 **96/96**, E2E **35/35**, 백엔드 계약 **22/22**, Next.js 빌드와 타입 검사 통과.

- `content.test.ts`: 버전 보존/선택/복원/번호 재사용 방지, 별도 저장소 작성자의 동시 충돌, 권한/필드/참조 검증, REST 우회 차단, 실패 시 생성 사용량 롤백, 스냅샷 위조 차단, 참조·콘텐츠 삭제 정책.
- `content.spec.ts`: 실제 UI 생성→본문/메타/설정 편집→새로고침→선택/복원/삭제, 503 입력 보존, HTTP 409 충돌 후 최신 읽기, 워크스페이스 전환, 모바일, 같은 작업의 재생성 스냅샷.
- Ego Lite: 직접 작성 v1→편집 v2→v1 복원 v3→새로고침·모바일→전체 삭제 확인. QA 항목은 삭제했다. [데스크톱](evidence/2026-10-23-content-editor.png), [390px 모바일](evidence/2026-10-23-content-mobile.png).

생성기는 결정적 데모 Provider이며 외부 AI를 호출하지 않는다. 제작 중 표시는 실제 요청의 대기 상태다. 서버 작업 큐/취소는 F10, URL 수집·최적화 제안의 실제 본문 적용은 P10, 내보내기/번역/외부 게시 설정은 P11에서 이어서 구현한다. 전체 메뉴 완료를 의미하지 않는다.
